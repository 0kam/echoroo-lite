# 検出品質の検証と報告値の補正

更新: 2026-09-09。**設計の検討記録と実装仕様を区別する。**
本文の相談案をもとにした初期実装は、末尾「2026-09-09 本番実装で採用した初期手順」を参照。
機能の動作確認は、実録音の検出品質を確認したことを意味しない。
最新の展示条件と、検出／検索の出力を分ける案は [reporting-design.md](reporting-design.md) を参照。
2026-09-09 のユーザー指定により、11/28 のプレビューに向けて検証データ作成を含む
フルワークフローを実装する。以下の統計手法・品質の採用条件は引き続き相談案。
通常の検出一覧の訂正は省き、人の判定を本書の検証と検索標本へ集約する提案に更新した。

利用者の希望は、実録音の検証データから種別の閾値を決め、precision / recall も
考慮した報告を、少ない確認作業で可能にすること。[要件](requirements.md)を具体化する。

## 1. 提案の中心

目的を二つに分ける。同じ人の判定記録を利用できるが、計算と表示は区別する。

| 用途 | 方法 | 出力 |
|---|---|---|
| 信頼しやすい候補を探す | 種・モデルごとに現地データで閾値を調整し、別の標本で評価する | 候補、precision、recall、不確かさ、検証条件 |
| 録音中の鳴き声の出現量を報告する | 検出外も含めた確率標本から、誤検出と見逃しを補正する | 鳴き声を含む固定区間の推定割合と不確かさ |

低品質の種へ一律に小さな係数を掛けると、見逃しの多い種をさらに過小評価する。
precision と recall の積や F1 を「生物多様性への寄与の重み」としては使わない。
個々の種の出現量を推定することと、種をまたいだ生物多様性指標の定義は別問題とする。

### 参照した Nature 論文との関係

ユーザー指定の [Kovács et al., 2026, Highly fragmented European wetlands with uneven restoration needs](https://www.nature.com/articles/s41586-026-10760-9)
は、sol サブエージェントが本文・方法と関連資料を確認した。
欧州の湿地面積推定では、土地被覆の層ごとに抽出した検証点の真の分類割合を、
その層の既知面積で重み付けして全体へ拡大する。各点の基本的な重みは
「層の面積 / その層の検証点数」であり、precision × recall ではない。
炭素量への換算には、推定面積に加えて文献の炭素密度と攪乱状態別の減少係数を使う。
面積の標本誤差と炭素換算の仮定は区別される。

音響への応用案は、面積を区間数へ、検証地点を確認する音声区間へ置き換えること。
論文の国別推定にある高度な重み調整・部分プーリングまで初回実装へ持ち込む必要はない。
また同論文の専門家による参照分類と、アプリ利用者による音声判定は同等ではないため、
下記の人の判定の品質を別途扱う。

## 2. 利用者が行う操作（提案）

1. 地点・録音群・期間を選び、まず報告したい一種〜少数の種を指定する。
2. 必要なら参照音源で学び、未見の正解付き問題で種別の判定能力を確認する。
   練習用の録音と能力評価用の録音を分ける。現地検証の音を本人が回答しただけで
   正解付き問題に昇格させない。能力評価との連携は第 6 節の追加案を参照。
3. アプリが確認する区間を抽出する。利用者は音声・スペクトログラムを見聞きし、
   対象種について「聞こえる／聞こえない／判断できない」を回答する。
   全種の網羅同定や発声の境界描画を必須にしない。
4. 10 問程度ずつ中断・再開でき、同じ区間への一度の回答で両モデルを評価できる。
   AI の種名・スコア・抽出理由は回答前に見せず、前後の再生と参照音源へのアクセスを用意する。
5. 調整用データで種別閾値を提案する。例として「適合率 90% を目標に、なるべく
   見逃しを減らす」。**90% を既定の目標にすることでユーザー合意（2026-09-09）。**
   達成は独立した評価区間と不確かさで別途判断し、未達の場合も結果を表示する。
6. 閾値を固定し、独立した評価用データで precision / recall と不確かさを表示する。
   根拠が足りない場合は「検証不足」とし、見かけの高得点だけで品質達成としない。
7. 図には AI の原集計、人が確認した記録、統計的に補正した推定値を区別して表示する。
   推定値には対象範囲、参照判定の作成方法、評価標本数、モデル版、閾値、区間幅を添える。

## 3. 少ない判定を有効にする抽出

**全解析区間を対象に、モデルスコア帯で層化し、各層内では無作為抽出する。**
高スコア・閾値付近を多めに確認しつつ、低スコア・未検出の層にも抽出機会を残す。
単純無作為抽出は比較基準として残す。モデルを抽出効率化に使うこと自体は問題ではなく、
全体をカバーし、既知の抽出確率で全体へ戻せることが条件となる。

- 層ごとの全区間数、抽出数、乱数 seed、標本 ID、抽出規則・確率を保存する。
- 両モデルの不一致も有用な抽出軸だが、層を細分化しすぎると必要判定数が増える。
  最初は少数の固定した層で比較し、両モデルを共通の標本と適切な重みで評価する。
- 任意の類似検索や高スコア順の確認は、種を見つける作業として有用。
  抽出確率が分からない記録を、確率標本へ無条件に混ぜて性能推定しない。
- 隣接区間の類似性と録音日・時刻の偏りを考慮する。広い期間へ分散させ、
  日や録音単位で抽出する設計なら、その集団単位を不確かさの計算にも反映する。
- 検証中に都合のよい例だけを追加し、通常の固定標本用の区間推定で品質達成としない。
  初回は評価数・配分を事前に決める。小分けの UI と、統計的な終了条件を区別する。

## 4. 閾値・precision / recall

種・モデル・集計窓・前処理・地域フィルタ・対象データの組を一つの評価条件とする。
種ごとにその条件で閾値を調整し、条件が変われば評価の適用範囲を見直す。
生スコアをそのまま正答確率とは呼ばない。

層ごとに異なる割合で抽出した場合は、標本の単純な正誤件数を使わず、
区間の抽出確率の逆数で TP / FP / FN / TN を全体に復元する。
その加重件数から precision = TP / (TP + FP)、recall = TP / (TP + FN) を推定する。
比率推定には有限標本の誤差があり、不確かさも抽出設計に合わせて計算する。

- 閾値調整用と最終評価用を、原則として録音・日などの単位で分けておく。
  独立評価は同じ対象範囲を代表するように設計する。一日だけでは日間の頑健性は評価できない。
- 同じ評価データを見て閾値や採用モデルを選び直した場合、その結果を独立評価済みと呼ばない。
- 目標 precision に達する候補の中で recall を重視する。目標を満たす根拠がなければ
  無理に閾値を生成せず、追加確認または未達とする。
- モデル一致・スコア平均・種別のモデル選択を新たな検出規則として使う場合、
  その規則全体を評価する。二つのモデルの一致を真値とは扱わない。
- 正例が得られない種の recall、検出陽性がない条件の precision は算出不能となり得る。
  未対応種と、対応するが見逃した種を区別する。

種別閾値の有効性を支持する BirdNET の研究はあるが、別地域の閾値を日本へ移植する
根拠にはならない。[Tseng et al., 2025](https://link.springer.com/article/10.1007/s10336-025-02260-w)
の公開要旨と、[birdnetTools の閾値計算仕様](https://birdnet-team.github.io/birdnetTools/reference/birdnet_calc_threshold.html)
を参照した。スコアそのものと正答確率の違いについては
[Wood & Kahl, 2024](https://link.springer.com/article/10.1007/s10336-024-02144-5) も参照。

## 5. 重み付きの報告値

推定対象は、まず「録音された固定区間のうち、対象種の鳴き声を含む割合」とする案。
種の個体数、発声イベント数、生息確率、種数とは区別する。

層 h の全区間数を N_h、無作為に確認した区間数を n_h、その中の正例数を y_h とすると、
判定が全て確定した場合の基本的な推定は次となる。

```text
推定正例区間数 = Σ_h N_h × (y_h / n_h)
推定区間率     = 推定正例区間数 / Σ_h N_h
```

例えば 10,000 区間について、検出された 1,000 区間の 90% が本物で、
検出されなかった 9,000 区間にも 5% の本物があると検証で推定されたとする。

```text
誤検出を除いた検出分 = 1,000 × 0.90 = 900
見逃し分の推定       = 9,000 × 0.05 = 450
合計                 = 1,350 区間（13.5%）
```

この例の recall は 900 / 1,350 ≈ 66.7%。同一の対象・窓・閾値なら
「検出数 × precision / recall」との関係もあるが、小さな recall で不安定になり、
別地点の値の流用もできない。基本実装は全層から直接推定する方針を提案する。

音響分野には、スコアの分位帯から確認音を抽出し、各帯の全体に占める割合で
重み付けして call density を推定する先行研究がある。
[Navine et al., 2024, All thresholds barred](https://www.frontiersin.org/journals/bird-science/articles/10.3389/fbirs.2024.1380636/full)
（[著者版の方法・数式](https://arxiv.org/html/2402.15360v1)）。
本案はその考え方を参照するが、区間幅・抽出配分・区間推定方法は本アプリ用に検証する。
同研究の Beta 分布を使う推定を採用する場合、事前分布と信用区間の水準を明示し、
特に希少種・正例ゼロで事前分布だけが推定値を押し上げないか確認する。

### spiral plot への適用と比較

- BirdNET の 3 秒と Perch の 5 秒を比較する共通窓として **15 秒**を試す案。
  各窓内の最大スコア等、集約規則を固定し、その規則に対して検証する。
  15 秒は未合意。鳴き声の途中で切れる場合は前後を再生するが、判定区間は固定する。
- 主な図の候補は、月・時間帯等ごとの補正した区間率。
  異なる録音努力を示し、無録音・未解析・未検出・検証不足を区別する。
- 年間まとめの precision / recall を、各月・時間帯へ一律適用しない。
  細かなセルへ補正値を出すには、その単位での根拠または較正関係の安定性が必要。
  初回は根拠のある粗い集計で推定値・区間を出し、細かな図の原検出と区別する案。
- 録音されなかった時間の発声まで自動的に推定しない。推定の対象は有効録音区間。
  周期録音による偏りや、鳴かない個体の存在は分類器の検証だけでは解決しない。

## 6. 人の判定の品質と負担の限界

「利用者の確認を参照した現地検証」として、参照判定の作り方を明示する。
非専門家の回答だけから、専門家水準の正しさを自動的に保証することはできない。

- 参照音源、混同しやすい種の比較、保留、後日の再確認を用意する。
  クイズを種別の判定能力の評価にも使う。ただし学習用の総合正答率を、そのまま
  現地音声のラベルが正しい確率へ変換しない。以下の追加案で条件を整理する。
- 保留は陰性にしない。保留を除いた precision / recall だけを品質表示に使わず、
  抽出重みを考慮した保留率を併記する。解決しない場合は、保留を全て陽性／陰性とした
  推定区間率の範囲等も示せる。この範囲は標本誤差の区間とは別物とする。
- 「数問正解なら品質保証」「全種を短時間で検証」とは約束しない。
  対象種を絞る、同じ判定を再利用する、識別困難な種は未達のまま扱うことで負担を抑える。
- 確認済みの根拠音源は種の存在の報告に使えるが、検出品質の推定値だけで
  生息の不在や正確な種数を保証しない。検索専用種も同様。

### クイズを利用した参照判定の品質評価（追加の相談案）

ユーザーから「内蔵クイズで検証データ自体の信頼性を評価できるのでは」と提案された。
これを、学習支援に加えた **判定者の種別能力の測定** として具体化する。

1. **学習**: 希望する種セットで繰り返し練習し、解説・比較音を提示する。
2. **能力評価**: 未見の、独立に正解を確認した区間を使い、実際の検証と同じ
   「聞こえる／聞こえない／保留」で回答する。正答の提示は回答後とする。
3. **現地検証**: 種別の能力評価結果と、その評価がカバーする音の条件を判定記録に添える。
   必要なら少量の正解付き確認問題を混ぜ、作業中の成績変化を調べる。
   確認問題は品質確認用と明示した機能として扱い、現地の集計・標本数へ混ぜない。
4. **報告**: モデルの性能に加え、参照判定者の評価問題数、見逃し・誤認・保留の内訳、
   評価日時、問題の録音条件を添える。苦手な種・条件では追加学習や再確認を提案する。

能力評価では、対象種の正例だけでなく、対象種がいないことを確認した負例も必要。
混同しやすい別種、遠い音、重なった音、異なる鳴き方等を含め、条件別に記録する。
種名の選択式クイズだけでは、「その種がいない区間で誤認しない能力」は測れない。
まず種別の感度（鳴いているときに拾える率）と偽陽性率（いないのに拾う率）、
保留率を問題数・不確かさとともに扱う。陽性・陰性を人工的に配分したクイズの
precision は、出現頻度の違う現地の precision と一致するとは限らない。

**正解付き問題の品質が出発点になる。** 学習用の自動生成問題と、能力評価に使える
確認済み問題を区別する。xeno-canto の録音単位の種名だけでは、切り出した全区間に
その種が鳴いていることや、別種が背景にいないことまでは確定しない。
評価用には区間ごとの正解・確認根拠・出典・版を持つ問題セットが必要になる。
アプリ側で再利用できる確認済みの小規模セットを用意し、利用者ごとに専門家へ
依頼しなくても使える形を目指す。具体的な提供案は次項。
少数種の正解確認は岡本さんが対応可能と確認済み。初期学習用は26種に確定し、
独立した能力評価に追加する未見素材・維持方法・提供範囲は未決。
当人の同じ回答や、評価対象の BirdNET / Perch の予測だけを正解にして循環評価しない。

練習と評価は切り出し区間だけでなく元録音単位で分離する。評価後に正解を見た問題は
学習履歴へ移し、再出題の成績を未見の能力評価に数えない。学習で改善した現在の成績を、
過去に作成したラベルの品質へ自動的にさかのぼって適用しない。保存するのは回答時点の
能力評価 ID、問題セット版、種別・条件別の結果と元回答であり、単一の信用係数ではない。

先例として [Ghani et al., 2025](https://www.nature.com/articles/s41598-025-00996-2)
の Dawn Chorus データの説明には、種同定テストの成績をアノテーションの採用条件とする
運用がある。同論文は xeno-canto の時刻・背景種ラベルの不足や、対象音が明瞭な録音と
現地の音風景との違いも述べている。この先例はクイズ利用の参考であり、本アプリの
採用基準や、テスト成績から現地ラベルの正しさへの数値換算を検証したものではない。

### 一人用アプリでの能力評価セットの準備・提供（基本方針合意・詳細相談中）

アプリは一人用のまま、**共通の確認済み問題セットと、端末内の受験履歴**を組み合わせる。
利用者が自作する練習セットに加え、開発側・協力者等が事前に正解を確認したセットを
提供する基本方針にユーザー合意。利用者は種・セットを選んで受験し、
問題を作るための同定作業は負担しない。以下の対象種・規模・配布方法は詳細案。

**確認済みの体制**: 岡本さんが少数の鳥種の音源・区間の正解を確認できる。
これを踏まえ、候補の収集・切り出し・セット化を開発作業で補助し、岡本さんが正解を
確認する分担を提案する。このセットは一般利用者向けに使い、作成者本人の独立した
能力評価には別途未見の素材を必要とする。

準備の最小手順:

1. 初期クイズはユーザー指定の `../koe-e-lab/sample_data` の26種を使う。
   現データは各種1音源のため、学習と独立した能力評価には別の元録音の追加が必要。
   能力評価用を拡充する際は、種ごとに複数の異なる元録音から候補を集める。
   xeno-canto 等で候補を探し、AI は抽出・優先順位付けの補助に使える。
2. 開発側の確認者が、UI 上で時間範囲を選択・再生して、出題区間における対象種の有無を確認する。
   陽性に加え、紛らわしい別種等を含む負例を用意する。全可聴種の網羅ラベルではなく、
   出題する対象種の有無を確認する形で負担を抑える。曖昧な候補は評価用に採用しない。
3. 素材の元録音単位で、学習用と未見の能力評価用に分ける。
   自然録音の問題を基本に、確認した素材から合成した問題は条件別評価として追加する。
4. 音源・区間・正解・対象種・出典・利用条件・確認者と確認根拠・版を一つのセットにする。
   同梱、または追加ファイルの取り込みで利用できるようにする案。取得後の受験はオフライン。
5. 利用者の端末が出題・採点・既見の管理を行う。評価対象外の種や、未見素材が足りない
   場合は未評価と表示し、同じ元録音の合成違いで独立した評価数を水増ししない。

開発側で共通セットを作る一度の確認作業を、多くの利用者が再利用できる。
配布元と録音の確認者は区別し、公式配布という理由だけで現地ラベルの品質を保証しない。
本人が素材の選定・正解確認をした場合、その本人にとっては学習用として扱い、
別の人が作った未見のセットがない限り、独立した能力評価済みとは表示しない。

最初はアプリが読む小さなデータセットを開発側で用意する。素材の登録・区間選択・
正解確認は、クイズと録音確認で共用する再生・範囲選択 UI を使う。
配布は同梱や追加ファイルで行える構成とし、専用の配布基盤は必要になってから検討する。
後日、研究者・団体等が作る同じ形式のセットを追加できるようにする案。
音源を同梱できるか、初回取得するかは各素材の利用条件に合わせて決める。

確認者を確保できない場合は、目的に合う既存の区間ラベル付きデータの利用可能性を
調べる。対象種・自然録音の条件・正例と負例の確認範囲が合う資料はまだ選定していない。
xeno-canto のメタデータや本人の判定だけから自動生成したセットは練習・参考成績として
提供できるが、それだけで現地検証データの正しさを独立に評価できたとは扱わない。

最初の対象種は `sample_data` の26種で確定。次に決める点は、出題区間、未見の能力評価用
素材の追加、提供形態。正解確認の担当と共通セットを提供する基本方針は合意済み。
素材の実物確認結果と一覧は [展示・報告設計](reporting-design.md) に記録した。

### 人の誤りを数値補正へ使う場合の条件（後段の検討）

同じ種・条件で、人の感度を a、偽陽性率を b、真の正例割合を p とすると、
保留がなく、評価した人の誤り率を現地に適用できる場合、人が陽性と答える割合 q は
`q = a × p + b × (1 − p)`。したがって `p = (q − b) / (a − b)` という関係を持つ。
これは「クイズ正答率を検出数へ掛ける」方式とは異なる。

ただしモデルのスコア帯で抽出しているため、人の誤りが帯・雑音・類似種によって
変わる場合は全体共通の a / b を適用できない。a / b 自体の推定誤差と現地標本の誤差を
ともに伝播する必要があり、a と b が近いと推定は不安定になる。保留も別途扱う。
範囲外の推定値を黙って 0〜1 に丸めて成立したことにしない。

初回は能力評価を **追加学習・再確認の案内と、検証記録の品質情報** に使う。
数値的な人の誤り補正は、正解が独立に確認された現地条件の音で、クイズ成績の適用性と
補正後の推定を検証してから加える。人と AI の双方の誤りを、両者の一致・不一致だけで
一意に推定できるとは仮定しない。

### クイズ素材の選択と合成による難易度変更（拡張案）

ユーザー案: xeno-canto の検索結果やオリジナル音源から、対象種だけが明瞭に入る
音源・区間を利用者が選び、音量調整・他種との混合等で問題の難しさを変える。
**オリジナル音源の追加と、UI 上の範囲選択による区間指定はユーザー合意。**
音量調整・混合は既存の NumPy / SciPy で始めることでユーザー合意。
拡張機能を初回必須とするかは未決。PyroomAcoustics は音響伝搬が必要になった時の候補とする。

想定する操作は「xeno-canto 検索／オリジナル音源を選択 → UI 上で区間選択・試聴 → 素材として保存 →
背景音・他種と難易度を選択 → 合成音を試聴して問題セットへ追加」。
素材には原録音 ID、出典・録音者・ライセンス、区間、種、選定者・確認状態を保持する。
他種や環境音も背景素材として扱い、同じ区間選択・再生の仕組みを再利用する。

区間選択の操作案:

- オリジナル音源は PC の音声ファイル、または取り込み済みの録音から選ぶ。
  xeno-canto の音源も同じ選択画面で扱う。
- 波形・スペクトログラム上で時間範囲をドラッグし、拡大と左右端の調整で範囲を決める。
  開始・終了時刻と長さを表示し、キーボード等でも微調整できるようにする。
- 選択範囲の再生・ループ再生で確認して保存する。前後を試聴しても、保存する範囲は
  明示した選択範囲を維持する。表示・試聴・保存が同じ時間範囲を指すことを確認する。
- 空の範囲・逆転した範囲・音源外の範囲は保存しない。原録音 ID と開始・終了位置を
  保存し、元ファイルは変更しない。正解・確認状態を区間に対応付ける。
- この自由な区間選択はクイズ素材作成の操作。モデル性能を比較する固定窓の定義は
  維持し、クイズの切り出し幅で評価の単位を変えない。

- **難易度の操作軸**: 対象音と背景音の相対レベル、混ぜる種、種数、重なる時刻。
  全体の音量だけを下げても利用者が再生音量を上げられ、信号対背景の比は変わらない。
  初回の合成は、相対レベルと時間の重なりを中心にする案。
- **成績の見方**: 種別に、明瞭な単独音・小さい音・類似種との重なり等の条件別で
  見逃し・誤認・保留を把握する。同じ設定値でも種や背景で難しさは異なるため、
  合成条件をそのまま客観的な難易度の尺度とは呼ばない。
- **正解の範囲**: 対象種の有無を問うなら、その種を混ぜない負例も作る。
  複数種の同定問題なら複数回答を許す。残存する背景種に注意し、投入した素材の
  種ラベルだけで全ての可聴種が確定したとは扱わない。
- **合成正解と聞こえ方**: 生成記録から分かるのは「対象音を投入した」こと。
  強く遮蔽されて識別不能な音まで、人が正答できる評価問題とは限らない。
  条件を試聴確認し、極端な条件は限界を調べる練習として区別する。
- **評価の独立性**: 自分で選んで聞いた素材は学習用として扱う。
  能力評価は別の未見の原録音を使う。原録音を共有する別区間・音量違い・混合違いを
  学習と評価へ分けない。派生問題の数を、独立した録音の数として数えない。
- **再現**: 合成に使う全素材の ID・区間・ゲイン・配置時刻・乱数 seed・処理版を残す。
  原音源は変更しない。レートを揃えて合成し、クリッピングを防ぐ。
  合成後の出力調整は全体へ共通に適用し、設定した対象音と背景音の比を保つ。

Ponytail の方針に沿い、音量変更・時刻の移動・加算は既存の NumPy / SciPy で始める（合意済み）。
距離・方向・反射などの音響伝搬を扱う必要が出た段階で PyroomAcoustics を検討する。
同ライブラリには室内反射と自由音場のシミュレーション、SNR / SIR 調整の仕組みがある。
[PyroomAcoustics 公式資料](https://pyroomacoustics.readthedocs.io/en/stable/pyroomacoustics.room.html)
森林等の屋外録音の再現性は別途確認する。合成問題による成績は条件別の能力評価に
使えるが、現地検証への数値補正には自然録音でも適用性を確認する。

## 7. 最小実装と試行

まず既存の 12 時間の音源で少数種を対象に試す。これは一地点・一日の操作性と
計算の試行であり、年間・他地点に適用できる品質を証明する試験ではない。

1. 対象種を選び、比較用の固定窓と各モデルの全区間スコアを作る。
   現 PoC の上位 5 件と BirdNET の保存下限だけでは、下位スコアの較正ができない。
   全クラスの巨大な常時保存を先行せず、まず検証対象種の全区間スコアを保持する。
   地域フィルタによる除外と、低スコア・モデル未対応を区別する。
2. 少数の層と事前に固定した抽出数で確認セットを作る。判定時間と保留率を測る。
   データ ID、対象種、区間、回答、回答履歴、モデル版、抽出情報、調整／評価の区別を保存する。
3. 種別閾値、加重 precision / recall、補正区間率を試算し、ユーザーと表示を確認する。
4. 正解が既知のデータで抽出を反復し、推定の偏りと区間の被覆率を検証してから
   報告機能へ載せる。新しい日・季節のデータで評価の持ち運び可能性も確認する。

初回から複雑な階層ベイズ、モデルの自動合成、全種の自動較正、独自の総合生物多様性
スコアは実装しない。必要な原スコアと人の判定を保ち、少数種で成立する流れを先に確認する。

## 8. 次に相談する点

- 公開したい主な成果は「確認できた種の一覧」と「鳴き声の出現パターン」のどちらが中心か。
  前者は根拠音源の確認、後者は検出外を含めた集計補正の優先度が高い。
- 15 秒単位の有無判定で扱いやすいか。最初に試す対象種と、許容する確認時間。
- 候補の precision の目標値と、最終評価でどの不確かさまで許容するか。
  点推定と区間下限のどちらを達成条件に使うかで負担が変わる。
- 検証不足・保留が多い種について、原予測の参考表示と報告用表示をどう分けるか。

## 2026-09-09 本番実装で採用した初期手順

画面フローと precision の目標90%はユーザー合意。以下の標本設計・数値は、
その方針を実装可能にする開発上の選択であり、個別に承認済みの統計仕様という意味ではない。
実装は `apps/sidecar/validation.py`、確かめ方は `test_workflow.py`。

- 両モデルの保存済み出力から、非重複15秒区間を作る。各モデルのネイティブ窓の最大スコアを使う。
  15秒を満たさない録音末尾、モデル未解析・種が地域フィルタ外の窓は、そのモデルの母集団に含めない。
  解析済みの特定期間の有限個の区間が対象であり、未録音時間・将来・他地点へ外挿しない。
- 調整用は両モデルの最大スコアで3層（<0.1 / 0.1–0.5 / ≥0.5）。各層から20音まで無作為非復元抽出し、
  必ず半分以上を残す。最大60音。重みは層内区間数 / 抽出数。閾値0.01–1.00を0.01刻みで比較する。
  対象音が3件以上あり、重み付き適合率90%以上の中から既知陽性に対するrecall最大を選ぶ。
  調整中の「判断できない」は適合率を過大評価しないよう検出側で非陽性として扱う。
  条件に合う閾値がなければ探索用0.1を固定する。この調整値自体を品質保証に使わない。
- 閾値固定後、調整に使わなかった区間を、各モデルの検出 / 非検出 / 適用不可の組で層化する。
  各層最大60音を固定抽出する。両モデルが全区間に適用される通常条件は最大240評価音。
  アプリは実際の必要数・回答数を表示し、10音ごとに中断できる。途中の高得点を理由に評価を終了しない。
- 分割の単位は**15秒区間**で、録音日や元ファイル単位のホールドアウトではない。
  同じ録音の隣接区間が両側に入り得る。有限母集団の固定された参照ラベルに対する確率抽出として計算する。
  人の学習・同定の誤りや日をまたいだ汎化性能は、この標本誤差では評価していない。
- 評価層の真の陽性数について超幾何分布の両裾を反転し、層数によるBonferroni補正で同時95%区間を作る。
  そこからprecision、recall、鳴き声を含む区間の割合の上下限を計算する。
  「判断できない」は削除せず、全て陰性の場合〜全て陽性の場合の範囲を含める。
  未解決が残る場合の点推定は出さず、幅を示す。参照陽性が0の場合はrecallを算出不能とする。
  不確かさの下限が90%以上のときだけ目標達成を支持する。評価完了と目標達成は別状態。
- **評価済みの閾値を図と集計にも適用**し、未達のときも同じ閾値での品質を示す。
  録音・解析・対象期間が変わると適用しない。過去の回答と出力は保持する。
  推定割合は評価パネルとquality.csvに出し、探索用spiral plotは実際のモデル検出率を示す。
- クイズは同定の練習と検証への復帰をつなぐ。提供された素材の反復成績を独立した能力評価には使わず、
  クイズ点数による自動重み付けも行わない。能力評価用の未見・確認済みセットは本書の別設計事項。

数値計算は既存の [SciPy hypergeom](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.hypergeom.html) を使用。
有限母集団・非復元抽出の扱いは [NIST Sampling Primer](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.1500-28pt2C.pdf) を参照。
上記の層の組み方、同時区間の合成、適用条件は本アプリの実装判断である。
