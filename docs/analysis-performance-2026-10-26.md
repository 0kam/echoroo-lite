# 解析パイプライン性能調査（2026-10-26）

採用した変更は、ジョブ内の更新・保存用SQLite接続の再利用と、ORTモデルSHAの既存キャッシュ利用。推論設定、バッチ数、リサンプリング、圧縮形式、モデルファイルは維持した。新しい依存は追加していない。

## 条件・再現方法

- 基準コード: `d9f4b68`。macOS 26.5.2 / arm64 / 12 CPU、Python 3.11.15、ORT 1.29.0、NumPy 2.4.6、SciPy 1.17.1、SoundFile 0.14.0。モデルSHAと各試行の数値は [JSON](benchmarks/analysis-2026-10-26.json) に保存した。
- 各試行は新しいPythonプロセスと使い捨てカタログ。科学計算ライブラリは事前に予熱し、計画作成からモデル読込、解析、保存、overview作成、モデル・DBの後処理までを計測。音声生成・インポート・数値比較は計測外。試行は直列実行。OSキャッシュ・他アプリ・CPU周波数は固定していない。
- 入力は重複しない固定seedの環境雑音、低周波の風、昆虫音と、音量を変えた実際の鳥声。WAVの長短構成は同じ音列を分割する。[鳥声の出典](../scripts/fixtures/README.md): XC1177906 / steve / CC BY-SA 4.0。利用者のカタログと音声、`poc/models` は変更しない。
- 以下はジョブ全体の実測で、アプリ内の「限界費用」ベンチマークとは異なる。各段階は同一スレッド内で排他的に計測。prefetchは別スレッドの時間が重なる。`inference.birdnet` にはパッケージ内の48 kHz変換、IPC、結果回収も含む。BirdNET音響backend単体の数値は別記。

接続再利用の個別実験はreaderも含むプロセス内接続を共有した。製品コードではジョブの更新・保存用接続だけを共有し、モデルworkerの起動後に開く。各進捗と各録音/AIの保存は独立したtransactionでcommitする。ジョブ全体を一括commitする案は、キャンセル・途中失敗時の再開性を保つため採用しない。
6分の `inter-2` はSEQのままなので、新しいノード並列化を有効にしない比較対照でもある。測定差をそのまま性能改善とは判断しない。

全量120本の接続再利用単独実験は Perch +4.15 / +17.8%、Kinglet-S +2.37 / +34.4%。採用版全体の結果は上の全量表を参照。

## 同値性・検証・見積り

- 採用変更は全量Perch/Kinglet-Sの全18試行、およびONNX4モデルの3形状で、保存スコア・1536次元埋め込みがbyte単位で一致。各窓の全クラス1位、アプリの候補リスト内の既定閾値0.1の検出フラグも一致。Perchの比較では保存logitsと、全クラスsoftmax後に日本鳥リストを適用した検出を両方確認した。
- 不採用のFFT resampleはPerchで検出1、Kinglet-Sで6変更。polyphaseの軽いKaiser設定はKinglet-Sで7変更。これらは速度にかかわらず不採用。モデルのfp16/int8化は実施していない。
- 回帰テスト: 途中失敗後も完了したpairが保存されること、不完全なvec挿入はpairごとrollbackされること、WAL/FULLの維持、未解析pairの再開、計時の排他性、差分判定、bulk SQLの値とrollbackを確認。
- 見積りのAPIフィールド・推定式は維持。保存ベンチマーク形式を `marginal_v2` に更新し、古い値を破棄して実際の新経路で再計測する。
- 新規依存・モデル変更なし。Windows/Linuxの実測なし。既存CPU EPを維持する。将来の評価条件は、Windows DirectMLなら対応EPビルドとDirectX 12対応GPU/driver、Linux CUDAなら対応EPビルドとCUDA/cuDNN/NVIDIA環境。現wheelで利用可能なAzure EPには、このローカル音響モデル用の処理を追加していない。

公式資料: [ORT threading](https://onnxruntime.ai/docs/performance/tune-performance/threading.html)、[CoreML EP](https://onnxruntime.ai/docs/execution-providers/CoreML-ExecutionProvider.html)、[DirectML EP](https://onnxruntime.ai/docs/execution-providers/DirectML-ExecutionProvider.html)、[CUDA EP](https://onnxruntime.ai/docs/execution-providers/CUDA-ExecutionProvider.html)。
