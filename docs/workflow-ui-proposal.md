# 種を中心にした操作フロー案

2026-09-09。**画面フローはユーザー承認済み。本番実装・Mac 検証済み。**
実装と確認の記録は [mac-workflow-2026-09.md](mac-workflow-2026-09.md)。以下は画面案の記録。
Windows の確認へ移る前に、Mac の完成をユーザーへ報告する。
クリックして確認する [画面案](prototypes/workflow.html) は架空データを使い、解析・音声再生・
統計計算・実データ保存を行わない。画面内の操作記録はタブを閉じると失われる。
参照音検索・範囲選択・複数種実行・クイズの出題は表示位置と入口を示す段階。
クリックで確認できるのは画面遷移、回答の進捗、練習からの復帰、検索確認の一覧反映、
出力種の選択。これらを製品機能の動作確認とは扱わない。

## 合意した中心

目的は、検索・検出と検証に基づく信頼性評価が紐づいた生物多様性情報を出力すること。
録音群を開くと全体像が見え、種を選んで音・季節性・検証へ進む。
見つからない種も参照音から探せる。モデル対応種でもこの入口を使える。
不要な機能・選択肢は削除し、詳細設定に隠して温存しない。

## 画面案

1. **録音群の結果**：録音期間・解析済みの割合と、調べている種の一覧を表示する。
   AI の検出と、検索で人が確認した音の有無、検証状況を並べる。
   未検証の AI 一覧を「確認済みの生息種数」とは表示しない。
   「探したい種が見つからない」と「レポートを書き出す」がここからの入口。
2. **種の詳細**：共通名＋学名、検出の時期・時間帯（spiral plot）、根拠音と検証状況。
   BirdNET / Perch の結果は並べて確認でき、図のモデルを切り替えられる。
   「検出の確かさを調べる」「参照音からさらに探す」「この種の声を練習」をつなぐ。
3. **参照音から探す**：対象種を引き継ぎ、Xeno-Canto か PC 音源を選択して範囲指定。
   種を新しく指定するときはフリーワード入力から始める（ユーザー指定）。
   和名・英名・学名で種マスタ全体を検索し、完全一致を優先する。
   検出種やモデル対応種に限定しない。本番は既存の SpeciesPicker と `/species?q=` を再利用する。
   画面案の選択リストも検索入力へ修正済み。例示用の7種と未登録種の追加操作を試せる。
   一種から開始し、同じ操作で参照音や他の対象種も追加できる。
   検索開始時に条件を自動保存する。結果から対象種を確認し、元の種の詳細へ戻る。
4. **検出の検証**：対象種・地点・期間を確認し、確認音の組を作る。
   一区間ずつ「聞こえる／聞こえない／判断できない」。回答は自動保存し、中断・再開できる。
   両モデルの答えやスコアは回答前に表示しない。練習後も元の区間へ戻れる。
5. **出力**：対象期間・収録種・品質の状態を確認して、一つの ZIP を保存する。
   種一覧 CSV、図、根拠音、品質評価、解析・検証条件を一緒に保存する。
   書き出した結果は固定し、あとから同じ内容を参照できる。

結果閲覧に「報告作成」は要求しない。閲覧時の集計と、書き出す結果の固定を分ける。
図を描くためだけに保存履歴を増やさない。

## 承認した画面フローへの整理

| 現在の操作・項目 | 案 | 理由・残す要件 |
|---|---|---|
| サイドバーの「録音と候補」「類似検索」「報告」 | 録音群の結果と、そこからの種の操作へまとめる | 機能名を先に理解しなくても進める |
| 録音群の先頭にファイル一覧 | 結果を先頭、ファイルは「録音を見る」へ | 解析完了で成果が目に入る |
| 結果を見る前の報告作成フォーム | 削除 | 期間は録音群全体を既定とし、結果画面で変更 |
| 「候補にない種も指定して確認」 | 独立した集計操作を削除 | 見つからない種は参照音検索へつなぐ |
| モデル版の選択・ハッシュ文字列 | 通常の操作から削除 | 現在の解析版を使用し、版は出力条件に記録。古い出力は当時の版を保持 |
| BirdNET / Perch の比較 | 残す | ユーザー指定。両者を混合したスコアや品質は作らない |
| 報告の生スコア閾値入力 | 通常の出力操作から削除する案 | 検証前の探索用規則を明示し、検証後は採用済みの種別条件を使用。90% を目標に調整し、別の評価区間で確かめる。詳細は validation-design.md |
| 「試しに検索」「検索を保存して実行」 | 「検索する」へ一本化、条件を自動保存 | 試す・保存するを利用者に選ばせない |
| 検索する地点・期間の再指定 | 元の結果画面の条件を引き継ぐ | 実行前に対象範囲を表示。必要な期間変更は結果画面で行う |
| 検索の類似度帯と抽出数 | 残す。検索結果から「音を選んで確認」の段階に置く | 明示的な要件。検出品質の検証用抽出とは混ぜない |
| 参照音の複数追加・複数種検索 | 残す。一種の基本操作に「追加」を組み込む | 明示的な要件。最初から大きな設定表を見せない |
| 元録音の区間から検索 | 録音プレーヤーの範囲選択から直接進む | 別画面で録音を再選択させない |
| 検証の抽出方式・乱数・調整用／評価用の手動割当 | 利用者の設定にしない案 | アプリが決めた規則を記録。統計設計は別途合意する |
| 確認標本の番号を選ぶ | 種の「確認を続ける」にまとめる | 過去の判定・条件は参照可能にする |
| クイズの毎回の素材選択・問題数入力 | 種や既存セットから短い練習を開始する案 | セット作成、オリジナル音源、範囲選択は素材管理に残す |
| 出力の種類を多数選択 | 種一覧・図・根拠・品質・条件を一括 ZIP にする案 | 再現可能な一式を一操作で保存する |

言語・録音地点のタイムゾーン・入力ファイル・対象期間・対象種は意味のある選択として残す。
ライセンス・出典・未評価・不確かさも省略しない。

## 検証の入口と終わり

- 対象は一種〜少数種から開始し、録音群全体の全種確認を必須にしない。
- 作業開始前に対象範囲と今回の予定作業量を表示する。一区切りを例として 10 音とするが、
  10 音で品質保証できる意味にはしない。最終的な必要数・終了条件は未決。
- AI が検出しなかった区間にも確認機会を設ける。抽出条件・確率を保存する。
  閾値を調整する標本と独立評価用の標本を区別する（具体的手法は validation-design.md の相談事項）。
- 表示は「未評価 → 確認中 → 評価結果あり」。データが足りないときは「検証不足」と明示する。
  「評価結果あり」は高精度・合格・種の不在を意味しない。
- 結果には誤検出・見逃しの指標、評価区間、不確かさ、保留を添える。
  クイズの正答率を現地の品質数値へ自動変換しない。
- 既存のモデル版・対象範囲・条件が変わった場合、過去の評価を無条件に適用しない。
  適用可能な評価がないことを結果画面で示す。

## 空・処理中・失敗のとき

| 状態 | 主な表示と次の操作 |
|---|---|
| 未取り込み | 「録音を追加する」。地点と日時を確認して解析へ |
| 未解析 | 録音の概要と「解析する」 |
| 解析中 | 完了した録音数／全体、経過・見積時間、完成した結果の範囲。途中結果と明記 |
| 完了 | 同じ画面を結果に更新。他の作業中に強制遷移しない |
| 一部失敗 | 成功分の結果と未処理分を区別し、「失敗した録音を再試行」 |
| AI の検出なし | 解析範囲を表示して「参照音から探す」。不在とは表示しない |
| 検索で確認なし | 検索範囲・確認した音数・保留を表示。参照音の追加へ |
| 検証の中断 | 保存済み回答数と「確認を続ける」 |

## 出力の合意と残る相談事項

1. 未検証の種も「未評価」と明示してレポートへ含め、出力時に収録種を選ぶ方針はユーザー合意。
   信頼性を伴う成果として何を含めるかを決めるための選択なので残す。
2. 種別の検証を始めるときの目標と作業量をどう提示するか。
   最初から全種を要求せず、対象種を選んで予定作業量を確認してから始める案。
   品質目標の既定値と統計的な採用条件は、画面案の承認とは別に決める。

## 実装への切り分け

画面案で導線を確認した後、(1) 録音群の結果と種の詳細、(2) 種からの検索・自動保存、
(3) 検証データと品質評価、(4) 出力と練習への接続の順で進める。
既存の解析・音声表示・検索・図・出力を再利用する。検証の母集団・保存形式・評価版は
先に設計し、単なる画面追加で済むとは扱わない。

受け入れ確認は「説明なしで解析結果に到達できる」「見つからない種を探して元へ戻れる」
「検証を中断して再開できる」「根拠と品質状態を理解して一式を出せる」を日英で行う。

## 今回の画面試作の確認

- ブラウザで結果→種→検証、保留回答→練習→元の回答位置、中断→再開を確認。
- 10 回答後は「検証不足」と表示し、結果一覧にも反映。
- 見つからない種→参照音→検索判別→結果一覧への種の追加を確認。
- 英語への切替と、出力種の除外が出力内容のプレビューに反映されることを確認。
- 日英メッセージキーの一致、JavaScript 構文、Git 差分の空白チェックを確認。
- 種名フリーワード入力で、検出一覧にないカワセミを和名・英名・学名の部分一致から選び、
  参照音の選択へ進めることを確認。

上記は架空データによる画面試作の確認であり、製品の解析・検証機能の試験ではない。
