# 録音調査レポートの科学性と使いやすさのレビュー

2026-09-10のAstraレビューを、2026-09-11のユーザー訂正に基づき親エージェントが修正した。今回の修正をAstraによる再レビュー済みとはしない。ソース・17ページのモックの検査は9月10日時点の記録であり、今回アプリやモックを変更したことを意味しない。

**訂正した前提：検出・検索とも、人の検証データで種別閾値を調整し、結果全体へ適用して報告する。個別のAI検出を確認・訂正する工程は設けない。人が確認した種だけを掲載することや、検索を探索用閾値だけに留めることは完成仕様ではない。** 基本フローはユーザー再確認済み、統計手順や能力評価の詳細は引き続き提案である。

## 判断

**検出・検索の全対象区間を、検証データに基づく種別閾値で集計し、その基準の品質と限界を報告する。** 優先すべきは、報告対象の固定、両経路の閾値・集計・品質の接続、検証ラベルと判定者の能力評価の対応である。9月10日の個別確認を中心とするモックの前提は撤回する。検証標本の正例は根拠として残すが、全検出の人手確認を要求しない。

要約約2ページ、全種一覧、種別の図、参照音・検証標本・保存された確認記録を含む一式の構成は維持する。重点種、過去年比較、区域全体の保全効果、新しい総合スコアは追加しない。テスト成績は**検証ラベルの品質説明、判定の裏付け、検証標本の再確認や学習の案内**へ反映する案とする。総合点を検出数へ掛ける補正は採用しない。

行政担当者が判断材料として読める報告書を目指すことと、特定制度への提出適合を保証することは別である。環境省の手引き26ページは、目標に応じたモニタリングと見える化マップへの定期入力を案内している。今回の音声資料だけで区域の価値、計画の達成、認定基準の充足を判定する根拠にはならない。[環境省 地域生物多様性増進活動の手引き 概要編](https://policies.env.go.jp/nature/biodiversity/30by30alliance/documents/lowBio/30by30site-gaiyou.pdf)

## 重大度順の指摘

### R1 P1 報告対象の録音群を全経路で固定する

**問題と実害。** `storage.py` の `site_recordings` は、指定Datasetと同じ地点の全Datasetの録音を返す。地点中心UIとしては現行要件に合うが、今回の「当該録音群だけ」という報告の約束とは同一ではない。`reports.dataset_context()`、検証母集団、検索一覧、出力の録音一覧が同じ地点へ広がる。期間だけを絞っても、同じ期間の別の取り込みが入り得る。また、図を期間で絞ったのに概要の録音本数・時間や `recording_ids` が地点全体のまま残ると、本文と分母が食い違う。

**最小改善。** 報告開始時に、現在の文脈から対象録音ID集合と対象時間範囲を確定し、概要・図・検証適用判定・検索結果・根拠・一式出力へ同じ集合を渡す。本文に地点、期間、本数、録音時間を一度表示する。内部Datasetの説明や新たな階層入力を利用者へ要求しない。既存検索が広い範囲で行われていた場合は対象内の区間に絞るが、広い範囲で決めた閾値・品質を狭い報告へ無条件に転用しない。

**受入チェック。** 同一地点・同一期間に異なる取り込みA/Bを用意し、Aの報告へBの録音・正例・閾値の適用保証が混入しない。途中でBを追加しても保存済みA報告が変わらない。日付境界をまたぐ録音では、録音全長と対象内時間を混ぜない。

**利用者文例。** 「対象は今回選んだ1,392本、2026年6月の23時間12分です。同じ地点のほかの録音は含めていません。」数値は例であり、対象を固定した後に計算する。

### R2 P1 検証標本の判定区間を保ち AI例音と区別する

この指摘は既に人が判定した標本の由来の保存についてであり、AIの検出結果を個別にチェックする機能の追加ではない。人の判定・黒点のない区間も種別閾値に従って集計・報告する。

**問題と実害。** `reports.detection()` の根拠は閾値以上の15秒窓から選んだ最高スコアの3秒／5秒で、状態は `ai_candidate` のままである。`confirmed_windows` は増えず、一覧の確認数は主に検索正例から作られる。検証で15秒内に声があると回答しても、それが最高スコアの3秒に入っているとは限らない。検証正例を単純に既存候補へ貼り付けると、実際には確認していない短い音を「確認済み」として配る。閾値未満の正例を候補一覧だけから拾うと消えてしまう。

**最小改善。** 最新の有効な検索／検証回答を共通の根拠一覧へ集め、種、録音、回答対象区間、回答ID、判定時点、判定者を保持する。検証の根拠は確認した15秒を保存する。AIの3秒／5秒例は原予測の例として残してよい。検索5秒と検証15秒が重なる場合、種数・日数は重複させず、区間件数は窓幅の異なるものを単純加算しない。音源の重複収録を減らしても判定の由来は落とさない。

**受入チェック。** 最初の3秒は別音、後半だけに対象種がある15秒を陽性と判定し、後半を含む根拠が出る。閾値を上げてもその15秒の判定記録と音への参照が残る。一方、閾値以上の区間数・種数は新しい基準に従って再集計される。黒点から回答対象の始終時刻へたどれる。経路をまとめた種一覧で同じ種を重複して数えない。

**利用者文例。** 「黒点は、この時間帯に担当者が声を確認した区間があることを示します。正確な日時と確認した範囲は根拠一覧にあります。」現行図は時間セル中央に点を置くため、「点の位置が発声開始時刻」とは説明しない。

### R3 P1 検証ラベルの裏付けをテスト成績と接続する

**問題と実害。** 閾値調整・品質評価に用いる検証ラベルも、人の聞き分けに依存する。現行 validation_answers には判定者・能力評価IDがなく、クイズは練習である。人とAIが同じ別種を誤認すれば、一致率は高くてもラベルは正しくない。総合点や後日の得点向上で検証ラベル全体を格上げすると、判定時点の裏付けを失う。

**最小改善。** テストの種別結果を、回答時点で固定した品質情報として結び付ける。確認記録とAI評価を消さず、本文に「人の判定を基準とした評価」であることと、聞き分けテストの対象種・問題数・条件・未評価を反映する。練習成績だけなら「練習の記録あり／能力は未評価」。具体的な接続方法は次節に示す。

**受入チェック。** ウグイスだけの高得点でアオゲラの判定が格上げされない。未受験、練習のみ、未見問題の評価、現地に近い条件の評価を区別できる。高得点取得後も既存の回答・過去報告は変わらず、明示的な再確認は新しい回答履歴として残る。

**利用者文例。** 「検証用に抽出した音は担当者が判定しました。聞き分けテストで評価できた種と音の条件は付録に示します。この判定を使って種ごとの基準を調整し、解析結果全体を集計しました。」

### R4 P1 評価の分母 単位 推定値を図の原集計と区別する

**問題と実害。** 現行 `estimated_window_rate` とその区間は、調整用窓を除いた評価母集団に対する値である。図の候補率は全対象窓から計算される。両者を同じ「全録音の出現割合」と呼ぶと分母が違う。また15秒窓のprecision・recallは、日数、声の回数、個体数、種数の正確さではない。月間評価を毎時セルへそのまま補正係数として掛けても、その時間帯の品質は確認したことにならない。

**最小改善。** 原集計は「AIの候補になった15秒区間の割合」、推定は「人の判定を基準に見積もった、声を含む15秒区間の割合」と名付ける。各値に対象窓数と適用範囲を持たせる。初回は評価母集団の値をその範囲のまま出すのが最小である。全録音群の推定へ統合する場合は、調整用窓の固定済み参照ラベルを既知部分として足す方法を別途検証する。これは調整標本を再び無作為評価標本へ混ぜることではない。

```text
全体推定割合 = (調整用窓の既知正例数 + 評価側の推定正例数)
               / (調整用の適用可能窓数 + 評価側の適用可能窓数)
```

調整用に保留がある場合は、その部分も未確定範囲へ入れる。参照ラベルを変えた時点、種別・モデル別の適用不可窓も保存する。元の評価結果を上書きしない。

**受入チェック。** 全体100窓、調整20窓、評価80窓の例で本文とCSVが同じ分母を表示する。モデル片方のみ適用可能、末尾15秒未満、正例ゼロ、候補ゼロを手計算する。recallがないときに「見逃し0%」を出さない。時刻別の図へ月間の推定値・区間を貼らない。

**利用者文例。** 「候補率は全解析区間の集計です。確かさの評価は、基準の調整に使った区間を除く○区間を対象としています。鳴き声の回数や個体数の推定ではありません。」

### R5 P1 独立評価の意味と選び方を本文に正しく残す

**問題と実害。** 高得点の音や検索で見つけた音だけの確認を、全録音の品質評価へ混ぜると選択の偏りが入る。調整と評価で窓IDが重ならないだけでは、判定者が前後の音を覚えていないこと、未見録音での性能、別の日への一般化は保証されない。評価値を見て閾値や採用モデルを選び直す行為も、最初に固定した規則の独立評価とは異なる。

**ただし、現在の計算を過剰に否定しない。** 現在の目的が固定された有限個の録音窓で、参照ラベルを固定し、各評価層内で無作為に非復元抽出するなら、隣接窓の生態的相関だけを理由に超幾何分布の区間を無効とは言えない。問題は、人の回答が学習・記憶・提示によって変わることと、未録音時間や将来の性能まで結論を広げることである。日単位の分割を導入する場合も、対象日の偏りと抽出設計を見直さず、計算だけ同じにしてはいけない。[NIST Statistical Sampling](https://nvlpubs.nist.gov/nistpubs/SpecialPublications/NIST.SP.1500-28pt2C.pdf)

**最小改善。** 初回は現行の有限母集団設計を維持し、「調整に使わなかった区間による、今回の録音内の評価」と記す。評価時にAIスコア・予測・抽出層を隠す。確認途中に練習へ戻った場合は評価時点と能力情報を残す。評価結果を見た再調整は新しい版とし、同じ評価回答で達成を宣言しない。モデルを選ぶルールも結果を見る前に固定するか、選び直した事実を明記する。

**受入チェック。** 任意検索正例を何件追加しても評価TP/FNと標本数は変わらない。区間の一部を都合よく飛ばしても「評価完了」にしない。調整と評価のID交差は0。原録音・日単位では重なり得ることが方法欄に記載される。95%区間を全種・全図同時の95%保証と表示しない。

**利用者文例。** 「判定の基準を決めた後、その調整に使わなかった区間を無作為に選んで評価しました。今回の録音内での評価であり、別の時期や地点にも同じ精度があるとは限りません。」

### R6 P1 検索も検証データによる閾値調整と全結果の報告へ接続する

**問題と実害。** 正負中央値の中間は、例の選ばれ方と割合に左右され、誤検出・見逃しの目標を満たす根拠にはならない。現在はユーザーが指定した類似度帯からの標本も含めて、この目安が更新される。保存検索は全件の類似度を持つが、画面で見た上位30件や選んだ帯の回答割合を、そのまま検索全体のprecision・recallにしてはいけない。top-kの画面表示制約と全件保存の区別が必要である。

**最小改善。** 対象種・参照区間集合・モデル・集約規則・対象録音集合を固定し、人の判定標本から類似度閾値を調整する。その値を全検索区間の図・表・CSVへ適用し、個別確認済みのヒットだけに結果を絞らない。品質は候補外も抽出対象に含めた別標本で評価する。現行の中央値中点を評価済みへ言い換えるだけでは足りず、既存の全件類似度保存と検証の抽出・回答部品を接続する。未調整・品質未評価は条件に応じて明示する状態であり、検索を探索専用のまま完成とする方針ではない。

**分母の追加注意。** 保存検索は参照音と重なる対象区間を除外する。したがって埋め込み総数と、実際の検索結果の区間数は一致しない場合がある。`searched_segments` の事前件数だけを最終分母にせず、検索可能数、参照重複等の除外数、図の対象内区間数を区別する。対象録音内から選んだ参照音は、その選定自体が正例情報になり得るが、検索成功例や独立評価例として水増ししない。

**受入チェック。** 正例3・負例3から中央値の目安が出ても「品質評価済み」にならない。画面表示件数を30から10へ変えても保存図の分母は変わらない。参照音を1本追加すると旧閾値の品質保証が外れる。対象内参照の除外区間数が再現できる。

**利用者文例。** 「検証用の音を判定した結果から、この種と参照音の組合せに使う基準を決め、検索対象全体に適用しました。正確さと見逃しの評価は別表に示します。」独立評価が未完了なら末文を「正確さと見逃しはまだ評価していません」とする。

### R7 P1 根拠番号と配布する音の欠落を防ぐ

**問題と実害。** 現行出力はモデル例5件、検索の確認音20件まで同梱する。根拠CSVに残っていても音が付かない場合があり、「一覧のすべての確認を音で確かめられる」とは言えない。参照音はまだ同梱されない。最新モックは参照音2種のみで、検出・検索の根拠音は架空のため収録されないことを明示しており、モックとしては誤りではない。ただし、実データ一式の完全性検証は別に必要である。

**最小改善。** 本文・表・黒点から参照する確認記録は、対象区間の音または同梱しない理由へ必ず到達させる。PDF内に全明細を詰め込む必要はなく、全確認記録をCSV／HTMLに持たせ、本文に全件数と掲載例数を分けて記す。参照音Rと調査根拠Eを区別し、全使用参照区間、原音・加工音のハッシュ、始終時刻、変換条件、出典・ライセンスの既知情報を保存する。ハッシュは同一性の確認であり、種同定の正しさの証明ではない。

**受入チェック。** 検索正例21件目にも再生入口があるか、非同梱理由が表示される。全使用参照が一覧にあり、複数区間の同じ原音を重複収録しない。一式を別PCの日本語・空白入りパスへ移し、オフラインでPDF→番号→HTML→使用区間／原音を確認する。DOCXだけを渡したときにも「音は別添」とわかる。

**利用者文例。** 「声を確認した全○区間は別添の根拠一覧に収録しています。本文には代表例を掲載しました。参照音は検索のお手本であり、この地点の記録ではありません。」権利情報の欠落を推測で埋めず、実際に外部配布する素材の条件を個別に確認する。

### R8 P2 種別閾値の図で同じ色が同じ確かさに見えないようにする

**問題と実害。** 検出図の同じ候補率でも、種・モデルごとの誤検出率と見逃し率は異なる。検索図は、各参照区間との類似度の最大を取り、さらに時間セル内の最大を使うため、参照音が多い場合、参照区間が長く比較窓が増える場合、録音が多いセルほど、大きい値が出る機会が増える。種別閾値から1までを同じ色幅へ正規化すると、同じ赤が同じ類似度ですらなくなる。最新モック2ページの「色の基準は同じ種類の図でそろえる」は、そのままでは成立しない。

**最小改善。** 検出図は候補率0〜100%の共通色尺度を維持し、種別の閾値と品質状態を各種の注記へ出す。検索図は種・参照集合ごとの凡例にし、「色はこの検索内の似かた。別種・別の参照音の図とは比較しない」と記す。閾値を色の変わり目にする要望は維持するが、色を確率や共通の品質尺度に見せない。年・月・セル内の量を色だけから比べず、解析／検索した時間と区間数を添える。

閾値を適切に選んだ候補率も、そのまま真の声の含有割合とは限らない。スコア帯から標本を抽出して全体を推定する方法には先行研究があるが、その研究も分布の変化と推定の条件を検討しており、本アプリの値を自動的に保証するものではない。[Navine et al. All Thresholds Barred 著者版](https://arxiv.org/html/2402.15360v1)

**受入チェック。** 種Aの閾値0.3、種Bの0.8で同じ赤になっても「正解率が同じ」と説明されない。1参照から複数参照へ変えた図の条件表示が変わる。2区間中1区間と100区間中50区間で分母を読み分けられる。0.25／0.75の旧固定例が本文・図・CSVに残らない。

**利用者文例。** 「検出の色は候補区間の割合です。同じ割合でも、種によって間違い・見逃しの程度は異なります。」

### R9 P2 録音なし 未解析 対象外 0 保留を見分けられる図にする

**問題と実害。** 最新検索モック15〜16ページは「録音なし」の薄灰と「閾値未満」の濃い灰が近い。白黒印刷では一層判別しにくい。検出図も未録音の細い輪がほぼ白く見える。解析済みでも対象種が地域フィルタ外、モデル未対応、完全な15秒窓がない場合は0ではない。録音予定が不明なら「録音なし」を機器故障の「欠測」と断定できない。

**最小改善。** 0は白、録音なしは背景色と文字、解析・検索の対象外／未完了はハッチなど、状態を色以外でも識別させる。保留は人の判断の状態なので、候補率0の色へ変換しない。本文の録音量は日別の実時間、解析・検索の網羅性は有効窓数と時間で示す。録音本数だけの「100%解析」では末尾・フィルタの除外を隠し得る。

**受入チェック。** 同じページに録音なし、未解析、一部解析、対象種が対象外、有効窓が0、候補0、閾値未満正例を置き、色を消しても説明できる。1時間内の一部だけ録音したセルを1時間連続録音と説明しない。保留回答は陰性へ落ちない。

**利用者文例。** 「6月11日の録音はこの一式にありません。録音しなかったのか、保存されていないのかは、このデータからはわかりません。」

### R10 P2 要約の読みやすさを保ち 集計基準と検証の違いを説明する

**問題と実害。** モックの「AIが鳴き声を正しく数えられているか」は、鳴き声の回数の精度と読める。「推定95%」と「95%信頼区間」も非専門家には混同される。最新モックは1か月の4図配置では種名・凡例が読めるが、内側から外側へ日付を追うための目盛が少なく、特定の日を図だけで読むのは難しい。全種図の見た目が整っていても、最初の2ページから確認の裏付けまで理解できるとは限らない。

**最小改善。** 第1ページに対象範囲、閾値に基づく検出・検索の集計と基準の由来を置く。第2ページにその基準の正確さ・見逃し・評価範囲、検証ラベルの裏付けを置く。方法名やハッシュは付録へ回す。閾値に該当した日数を「人が声を確認した日数」と読ませず、個別の判定記録は分けて示す。図へ日付目盛を付け、詳細日時は表へ誘導する。1か月4図の配置を365日へ流用せず、文字を縮めない既定配置を使う。

**受入チェック。** 非専門家に要約だけを渡し、対象範囲、閾値による全体集計と検証標本の違い、95%の意味、見逃し未評価、基準の裏付けを本人の言葉で説明してもらう。説明で誘導せず、誤読を記録する。日英で同じ条件・日時を保持し、実寸・白黒で凡例を読む。DOCXを別環境で開いても日本語が消えないこととフォント条件を確認する。開発者の目視を理解テストの代用にはしない。

**利用者文例。** 「AIが挙げた候補60区間のうち、担当者は57区間にウグイスの声があると判断しました。この割合は95%ですが、候補全体でも同じ割合になるとは限りません。」57/60のWilson法95%区間は86.299〜98.285%で、旧文案の約86〜98%は計算上妥当。ただし現在の層化抽出に対する結果を、この単純標本の説明に置き換えない。

## テスト成績を反映する最小ロジック

### 1 何の能力を測るか

測るのは、検証標本で「この種の声が区間内にある／ない／判断できない」を答える能力である。全検出に人が同じ判定を付けるための試験ではない。26種の名前当て総合点だけでは、対象種がいない場面での誤認や、選択肢にない種が鳴いたときの判断を測れない。現在の4択は練習として維持し、能力評価は既存の検証と同じ3つの回答を使う。

種ごとに以下の表を保存する。全可聴種の完全な同定や、新しい多人数の合議システムを最初から要求しない。必要なのは、出題対象種の有無が区間ごとに確認された正例・負例である。

| 独立に確認した正解 | 聞こえると回答 | 聞こえないと回答 | 判断できないと回答 |
|---|---:|---:|---:|
| 対象種あり | TP | FN | U+ |
| 対象種なし | FP | TN | U− |

```text
正例数 n+ = TP + FN + U+
負例数 n− = FP + TN + U−
正例で拾えた率 = TP / n+
正例で「聞こえない」と答えた率 = FN / n+
負例で誤認した率 = FP / n−
負例で正しく「聞こえない」と答えた率 = TN / n−
保留率 = (U+ + U−) / (n+ + n−)
```

保留がない場合に、前者と後者は通常の感度・特異度に対応する。保留がある場合は、保留を除外した二値の感度・特異度だけを前面に出さない。「正例のうち拾えた」「負例のうち誤認」「判断を保留」を件数と割合で示す。回答を確定した問題だけの指標を補足するなら、その分母と回答確定率を明記する。負例0件の誤認率は0%ではなく未評価。

4択の種別混同行列は苦手な組合せの練習には使える。ただし、ある種が選択肢に出なかった問題を、その種を正しく否定したTNとして数えない。原音ラベルの種以外も背景にいる可能性があるため、単一種名ラベルだけから全種の陰性ラベルを作らない。

### 2 正解セットと未見性の条件

初期26種の `sample_data` は、各種原音1本・提供ファイル名によるラベルで、現在は練習素材である。岡本さんが区間の正解を確認できる点を生かし、まず少数の報告対象種について、異なる原録音由来の正例と、混同しやすい他種等の負例を追加する。原音のラベル、切り出し区間の正解、確認者、確認方法、問題セット版を分けて残す。

- 原録音単位で練習と評価を分ける。同じ原音の別区間、ゲイン変更、混合違いは独立した未見素材ではない。
- 出題前からスペクトログラムを表示する要件を維持し、正解種名・元ファイル名は隠す。見たことのある音自体の記憶は、名前を隠すだけでは消えない。
- 評価セットを作った本人の受験は練習として扱う。岡本さんが正解を確認した素材は他の利用者の評価に使えるが、岡本さん自身を独立に評価したことにはならない。
- 未見評価の正解は固定した評価ブロックの終了後にまとめて示す案を推奨する。逐次フィードバックで変化した能力を一つの固定能力の点数としてまとめない。練習では現行の即時フィードバックを維持する。
- 異なる元録音数、音の条件、テスト時点の参照音利用可否を保存する。現地で参照音を聴きながら判定するなら、同様の支援下で何を測ったかをそろえる。
- 明瞭な単独音の成績を、遠い声、重なった声、雨風、異なる鳴き方へ自動適用しない。音量・混合による合成条件と、自然録音で確認した条件は分ける。
- 合成で対象音を投入したという正解と、人が識別できる音であることは同じではない。強く遮蔽された問題は、安易に「能力不足」の採点に使わない。

無作為に選んだ自然録音の確認済み区間と、意図的に集めた難しい負例は、どちらも有益だが表す範囲が違う。前者は定義した条件の能力推定、後者は特定の混同の点検として報告する。問題を恣意的に選んだ場合、二項分布の区間を付けただけで現地を代表する試験にはならない。

### 3 少数問題の結果を過大評価しない

満点でも標本数が少なければ能力は十分に絞れない。独立で同条件の二項試行を仮定した両側95% Clopper–Pearson区間では、10/10正解の下限は約69.2%、20/20は約83.2%、36/36は約90.3%である。これは標本数の意味を示す計算例であり、36問を一律の合格基準にする提案ではない。複数種・複数条件を同時に保証する数でもない。

26種すべてに正例36・負例36を課すと1,872問、1問15秒の再生だけで7.8時間になる。聞き直しや回答時間は別である。初期版で全種の保証を約束せず、必要な種から短いブロックで受け、少数問題は「参考」として残す。途中成績を見て都合のよいところで止めた試験を、固定標本の達成判定へ流用しない。再受験は履歴を残し、最高得点だけを採用しない。

### 4 点数が何を変えるか

| 成績の状態 | レポートへ反映する内容 | アプリの最小動作 |
|---|---|---|
| 未受験 | 「検証ラベルを付けた担当者の聞き分けは未評価」 | 閾値に基づく結果と標本の回答は保存・出力可能。自動で専門家確認済みにしない |
| 現行4択・反復・自作／既見素材のみ | 種別の練習件数と成績。「練習の成績であり、実録音の正しさは未評価」 | 同じ種の練習へ戻れる。AI品質値や確認数へ係数を掛けない |
| 独立した正解付き未見問題を受験 | 対象種のTP/FN/FP/TN/保留、問題数、原録音数、日時・条件 | 標本の判定時点に結び付ける。誤認した種・条件の検証標本を再確認できる |
| 明瞭音だけ、または正例／負例・種の範囲が不足 | 測れた項目と未評価項目を併記 | 受験済みという理由で不足条件を埋めない |
| 現地に近い独立問題でも評価 | 同条件での聞き分け結果を判断の裏付けとして併記 | なお個別の声の正解確率にはしない。人の誤り補正は別検証後 |
| 判定後に新しいテストで改善 | 現在の成績と過去判定時の成績を別に保持 | 古い音を聴き直して回答した場合だけ新しい判定履歴を作る |

**得点の内訳と適用範囲によって、検証ラベルの品質説明と標本の再確認の案内を変える。** 「80点以上で採用」「合格種だけ報告」といった境界は作らず、個別の検出チェックも追加しない。実際の誤認・見逃しの種類を示し、未評価や少数問題を隠さない。標本の正例判定に曖昧さが残るなら、回答履歴を保って保留へ戻せるようにする。

**例文。** 「ウグイスの聞き分けテストでは、声がある10問中8問を拾い、1問を見逃し、1問を保留しました。声がない10問では1問をウグイスと判断しました。明瞭な単独音での結果で、雨音や重なった声は未評価です。」これは架空例であり、実際の評価は元回答から自動生成する。

### 5 保存データは回答時点に固定する

一人用アプリなのでログイン・複数権限は追加しない。端末内の判定者ID一つと、必要なら報告者名を既存設定に持てばよい。氏名だけで専門性を推定しない。既存の版付きsnapshotと追記式回答の仕組みを使い、少なくとも次を対応付ける。

| 保存対象 | 最小限の内容 |
|---|---|
| 能力評価snapshot | 評価ID、問題セット版、原録音と区間ID／ハッシュ、正解確認根拠、回答と日時、種別集計、条件、既見状態、目的が練習か能力評価か |
| 現地の回答 | 録音と区間、対象種、判定、回答時刻、判定者ID、回答時点で適用した能力評価ID／未評価理由、参照音利用等の判定条件 |
| 報告snapshot | 対象録音・解析・閾値・検索参照の版、採用した回答IDと締切時点、能力情報、集計方法、出力版 |

「最新のテスト点数」を出力時に動的参照するだけでは不十分。判定前の能力評価がない過去回答は未評価として残す。再評価で正解セット自体に誤りが見つかった場合は、該当セットに結び付く判定を再確認候補として示し、過去の保存報告を黙って書き換えない。未見性を扱う履歴は原録音の派生関係で判定し、ファイル名変更や再切り出しだけでリセットしない。

### 6 何を数値補正できるか

単純な総合点×候補区間数、総合点×precision、precision×recallによる種の重み付けは、誤りの仕組みに対応しない。見逃しが多い人ほど正例数をさらに減らす補正になり得る。同じ90%の正答率でも、正例に強いか、負例の誤認が多いかによって結果への影響は逆になる。

**条件が成立すれば人の誤りの補正は数学的に考えられる。** 保留がなく、対象種・条件で人の感度を `a`、偽陽性率を `b`、真の正例区間割合を `p`、人が陽性と答える割合を `q` とすると、

```text
q = a p + b (1 − p)
p = (q − b) / (a − b)
```

これは既存 `validation-design.md` の案と整合する。しかし、a/bは未見の確認済み問題で推定し、現地の雑音・類似種・モデルスコア帯へ適用できる必要がある。a/bとqそれぞれの標本誤差、原録音内の依存、保留を伝播し、a≈bの不安定さ、0〜1を外れる結果を診断する。範囲外の値を黙って丸めない。

さらに、**全体のpを補正できることと、AIのprecision・recallを補正できることは別である。** 後者にはAI陽性群・陰性群または評価層別の人の感度／偽陽性率が必要である。AIと人が同じ紛らわしい音を誤る場合、全体の人の感度を両群へそのまま使えない。両者の一致表だけから真の正解、人の誤り、AIの誤りを一意に求められるとは仮定しない。

クイズのprecisionも現地へそのまま移せない。保留なしで感度・特異度がともに90%なら、正例／負例が半々の問題での正答率は90%。しかし実録音の正例割合が1%の場合、「ある」と答えたものが本当の正例である割合は、仮に誤り率を移せても `0.9×0.01/(0.9×0.01+0.1×0.99) ≈ 8.3%` となる。これは仮定による説明例であり、利用者の実際の正確さではない。

**実装順序案。** 第1段階は現行練習成績を種別・目的付きで報告へ添え、未評価を明示し、現地回答との時点の対応を作る。第2段階は少数種の独立評価セットと3回答を加え、種別内訳・条件・再確認の案内へ反映する。第3段階は独立に正解を確認した自然録音で、人の誤り補正の適用性と被覆率を検証する。第3段階を待たず、第1・2段階で利用者に意味のある反映はできる。

## 要約2ページへの反映案

構成の追加より、既存の文章と表を置き換える。要約へ全種のテスト得点表や数式は入れない。

| ページ | 残す内容 | 変更する点 |
|---|---|---|
| 1 | 今回の主結果、閾値に基づく検出・検索の種別集計、対象録音の本数・日数・時間、録音量の図 | 基準の由来を示す。報告に種を選択した場合は「掲載した種」の数と全結果の数を区別 |
| 2 | 集計の確かさ、図の読み方、今回わからないこと | 検出・検索の精度と見逃し、検証ラベルの裏付けを示す。種ごとの詳細へ案内 |
| 種一覧 | 一般名＋学名、経路、閾値と集計、品質、図のページ | 個別の人手確認で掲載を制限しない。未調整・品質未評価も明記 |
| 種の詳細 | 全対象区間から作ったスパイラル図・表、検証記録、参照音 | 適用閾値、評価単位・範囲、テストの種別内訳、標本の判定を対応付ける |
| 一式 | 原予測、確認記録、推定値、CSV／JSON、参照音・根拠音、オフラインHTML | 同じ保存時点から出力。全参照と掲載した根拠へ到達可能にする |

短い結果の文例は「検証データから決めた種別の基準で集計すると、○区間が○○の検出に該当した。基準の正確さと見逃し、検証標本を判定した担当者の聞き分け評価は付録に示す」。未検証なら「この種は既定の基準で集計し、品質は未評価」とする。検索も調整した類似度閾値を全結果へ適用して説明する。個別確認の記録は補足できるが、地域での不在、繁殖、個体数、区域内の位置へ広げない。

## 実装後の受入チェック

以下は本レビューで実行済みの検査ではなく、提案を実装した後の受入条件である。

| 項目 | 必須の確認例 |
|---|---|
| 対象範囲 | 同一地点の別取り込み、同日、日付またぎ、追加取り込み、1年超の地点でも本文・全ファイルのID集合が一致 |
| 数値の一貫性 | 種別閾値と等しいスコアを含む。全窓と評価窓、15秒と5秒、日数と区間数を区別。原集計と補正推定の列を混ぜない |
| 全体への適用 | 検出・検索とも個別に未判定の区間を閾値で集計する。判定済みの種だけの掲載や全件確認を要求しない。標本の表示件数だけ変えても同一対象・閾値の集計は変わらない |
| 判定の保持 | 閾値未満の正例も検証記録に残る。モデル・検索の重複、保留、判定変更の由来を保持し、検証記録の件数と全体の閾値集計を混ぜない |
| 標本設計 | 既知の有限母集団で反復抽出し、正例希少・0・全陽性、小さい層、保留ありで推定と区間を検証。無作為標本以外を混ぜない |
| 能力評価 | 原音の既見・自作・別切り出し・混合違いを識別。正例のみ／負例のみ、対象外種、少数問、再受験、セット正解の訂正を扱う |
| 時点 | テスト後の成績改善、現地回答の再確認、モデル更新、参照追加で過去報告が変わらない |
| 閲覧 | 1種・30種・60種、短期間・年間・確認ゼロ、長い名前、途中表見出し、白黒、日英で情報が欠けない |
| 一式の完全性 | 20件を超す検索正例、複数参照、重複原音、非同梱理由、別PC・オフラインでの再生、DOCX／PDFの数値とページ参照 |
| 理解 | 非専門家が対象範囲、閾値による全体集計と検証標本の違い、検証ラベルの裏付け、正確さと見逃し、色の意味、根拠音への到達を説明できる |

モデル評価の目標90%は既存の合意を維持する。人の能力テストの合格点、種別に必要な問題数、数値補正の採用条件まで同じ90%と決まったわけではない。新たな閾値や厳しい全種受験をユーザーへの当然の要求にしない。
