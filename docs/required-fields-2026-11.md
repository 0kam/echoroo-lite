# 入力が足りないときの案内（2026-11-02）

ユーザーへのフィードバック（2026-11-02）：録音を追加するとき地点名を入れ忘れると「追加」が押せないが、その理由に気づかなかった。どこを埋めれば進めるのかを案内する UI になっていない。全体を探して直し、開発中のブランチとは別にリリースする（ユーザー指示）。

## いまの作り

入力が足りないと主なボタンを押せなくし（disabled）、ボタンの下に14pxの灰色で理由を出している。

- 押せないボタンは色が薄く、押しても何も起きないので、理由の文に目が行かない。
- 理由がまとめて書かれ（「地点名と、地図の場所（緯度・経度）」）、どの欄が空なのかを示さない。
- 空の欄が画面の外にあることが多い（録音の追加では大きな地図の上）。

## 決まり

利用者の入力を待っているボタンは押せるままにする。押したときに足りないものがあれば、処理をせずに次の3つを行う。

1. 足りない欄それぞれに、その欄のすぐ下に短い案内を出し（例：「地点名を入れてください」）、欄の枠をエラーの色にする（`aria-invalid="true"`、案内は `aria-describedby` で結ぶ）。
2. 最初の足りない欄へ移動してフォーカスする（画面の外なら見える所までスクロールする）。
3. ボタンのすぐ近くに、足りない項目の名前を並べた一行をエラーの見た目で出す（例：「まだ入っていない項目：地点名、フォルダ」）。

ほかの決まり：

- 押す前でも、ボタンの近くの一行で、まだ足りない項目の名前を具体的に示す（いまの灰色の理由の文を、項目の名前が分かる文に置き換える）。押した後はエラーの見た目に変わる。
- 欄を埋めたら、その欄の案内とエラーの色はすぐに消える。
- 入力とは関係のない「待ち」（フォルダを調べている途中、解析中、保存中など）は、今までどおり押せなくしてよい。その理由はボタンの近くに出す。
- 「（必須）」の印を全部の欄に付けることはしない。
- 文言はメッセージのキーで日英両方に用意し、大学1年生が分かる言葉にする。

## 対象（2026-11-02 の調査）

| 画面 | ボタン | 足りないもの |
|---|---|---|
| 新しい地点を追加・録音を追加（`datasets/new`） | 録音を追加 | 地点名、地図の場所（緯度・経度）、フォルダ |
| レポートを書き出す（`datasets/[id]/reports`） | レポートを作る | 収録する種、書き出し先フォルダ（ブラウザ版のみ） |
| 一覧にない種を探す（`datasets/[id]/search`） | 探す・お手本を足す | 種、お手本の声 |
| クイズに使う鳴き声を追加（`QuizEditor`） | 保存 | 種、音声、区間など（実装を確かめる） |
| 種の追加（`SpeciesPicker` の「未登録の種を追加」） | 追加 | 学名 |
| 練習する鳥を選ぶ（`quiz/choose`） | 組み合わせを保存 | 名前、鳥 |
| Xeno-Canto から選ぶ（`XenoCantoSearch`） | 探す | 種（API キー未設定は設定へのリンクで案内済み） |

地点と録音の管理（`sites/[id]/manage`）で、編集中に押せなくなるボタンは理由が出ているかを確かめ、出ていなければ近くに一行で示す。
