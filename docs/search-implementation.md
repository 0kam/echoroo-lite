# 類似音検索の初期実装（2026-09-08）

現在は「録音群 → 種ごとの複数参照区間 → 保存検索 → 類似度帯の無作為抽出 → 試聴・判定」まで接続した。
[出力設計](reporting-design.md) の閾値・報告図・CSVも接続済み。
集計定義と書き出しは [報告機能の実装](report-implementation.md) を参照。

## 音源と区間

- 登録済み録音、又は手元の WAV / FLAC / MP3 を選ぶ。後者はファイル名の日時を要求しない。
  参照音はモノラル／ステレオに対応し、ステレオは左右平均。元音源は変更・コピーしない。
- スペクトログラムは表示区間だけ読み込む。32 kHz に再標本化し、SciPy の STFT
  （1,024点、hop 256）を0〜12 kHzで表示。時間方向は最大1,000列に最大値集約する。
  明るさは表示範囲内の最大値から70 dBの相対表示であり、測定音圧ではない。
- 時間区間は横ドラッグ又は秒数入力。表示幅は5・15・30・60秒。
  選択区間の試聴と、検索結果の試聴には同じ部品を使い、別の音源へ切り替えると前の再生を止める。
- 検索の参照範囲は0.2〜30秒。ファイルのサンプル境界へ外側に丸めて読み、
  32 kHzに再標本化した後、先頭から5秒ごとに分割、末尾のみ無音を加えて5秒にする。
  要求した区間・実際のサンプル区間・各モデル入力区間・無音の長さ・モデルSHA-256・
  元ファイルのサイズ／更新日時をAPI応答へ付ける。UIで入力区間と無音の長さを確認できる。
  デジタル無音だけの参照区間は拒否する。

## 順位と検索対象

- 各対象窓と各参照窓の cosine similarity を求め、参照窓間の最大値を使う。
  [sqlite-vec の cosine distance](https://alexgarcia.xyz/sqlite-vec/api-reference.html#vec-distance-cosine-a-b)
  の `1 − distance` を単一区間の試行検索に使用する。保存検索は同じ cosine を NumPy で256ベクトルずつ計算し、
  全対象区間の最大類似度と、一致した参照音・参照窓を保存する。−1〜1の高い順、同点は区間ID順。
  識別の正しさの確率ではない。
- 指定した録音群について各録音の最新 Perch 解析を取り、そのモデルSHA-256が今回の参照埋め込みと
  同じ場合だけ検索する。古い解析や別の録音群を全体の上位検索へ混ぜてから除く方法は採らない。
- 種・地域の絞り込みは行わない。モデルが分類できない種を探すため、保存した全埋め込みを使う。
- 元ファイルパスと時間が重なる参照区間自身を除外する。同じファイルを参照音として別登録しても除外する。
- 全録音数／検索対象録音数／解析済み区間数を表示する。区間数は自己区間を除く前の解析済み窓数。
  未解析・モデル版不一致の録音を含む場合は明示する。対応解析がなければ先に解析するよう案内する。
- 参照音と検索対象の元ファイルについて、登録時のサイズ・更新日時を確認する。変更・欠落時は検索を止める。

## 参照音と検索履歴の保存

- 種を選び、スペクトログラムの選択区間をセットへ追加する。複数種は別々の検索履歴、
  同じ種の複数音源・複数区間は最大類似度へまとめる。1回20種・1種20区間まで。
- 編集中のセットは録音群ごとに UI のローカルストレージへ保存する。
  実行したセットは SQLite に別の履歴として保存し、追加・再検索で以前のセットを書き換えない。
- 保存検索には種 UUID・表示名、地点・録音群、モデル SHA-256、参照音の元ファイル情報・
  入力区間・無音補完、対象解析 ID と対象範囲を記録する。
  元解析／録音は既存の不変行へ関連づけ、地域ラベル一覧を検索ごとに大量複製しない。
- 検索履歴の初期表示は上位30件だが、SQLite は全対象区間の類似度を保存する。
  参照音自身の区間を除いた件数を画面に表示する。報告図はこの全件を集約する。
- 類似度の下限・上限・希望件数から、帯域内の全候補を等確率・非復元で無作為抽出する。
  母集団数、希望件数、実際の対象 ID、乱数 seed、抽出順、方法・日時を保存する。
  母集団が希望件数より少なければ全件。表示は類似度順。抽出回同士の重複は許す。
- 対象種／対象外／不明を保存し、未判定と不明を対象外に含めない。
  判定は種 UUID × 元の解析区間に結びつけ、変更時は履歴を追記する。
  同じ種・同じ解析区間なら別の参照セットでも最新の判定を表示する。
  再解析で新しい区間 ID ができても旧検索・旧判定は残り、別の解析へ自動転記しない。
- `この区間だけで試す` は種を選ばず試行できる従来の検索で、結果は画面内だけ。

## 検索期間と抽出前の分布（2026-09-09）

検索画面に録音開始日の下限・上限を追加。地点の現地日付で両端を含み、空欄は制限なし。
日付をまたぐ録音は開始日で選んで全区間を検索する。参照音の日時は制限しない。
試行検索と保存検索に同じ条件を適用し、対象録音数の分母もその範囲とする。
保存履歴に日付と `recording_start_local` を残し、報告画面・PNG/SVG・CSVにも条件を添える。
従来の履歴は全期間の検索として引き続き表示できる。

保存検索では抽出前に全対象区間の20帯の分布と対象種／対象外／不明の最新判定数を表示する。
上位30件や抽出標本だけの分布にはしない。報告画面と同じ表示部品を使う。
APIテストはUTC日付との違い、日付越え録音、範囲外、未解析録音、端点±1、
標本数と独立した母数、判定更新、CSV条件、再起動後の条件保持を確認した。
年間試験の保存済み210,240区間で分布を含む読み出しは0.392秒、続く読み出しは0.293秒。
両回とも帯の母数合計は全ヒット数に一致。追加の年間推論は行っていない。

Mac配布版では本番DBの複製を使い、8月8日指定で2/24録音・720区間を検索した。
日英切替で条件と現地時刻が変わらないこと、逆転した期間では実行できないこと、
録音がない日付の案内が両言語にあることを画面で確認した。
検索報告のPNG/SVGに日付条件が入り、CSVの `search_start_date`・`search_end_date`・
`search_date_scope` も一致。2400×2605のPNGを目視確認した。
検索画面の分布は最新の保存済み判定、報告の分布は報告作成時点の判定と、説明を分けた。
再起動後にも検索期間・2参照・720区間と最新判定の分布を復元した。
検査後は期間入力を空欄に戻し、通常のアプリ用データで起動した。
更新したMac凍結版では30秒音声の両モデル解析22.22秒、参照検索0.95秒、
保存検索・抽出・判定0.40秒、報告・CSV出力0.21秒で正常終了。26種クイズも通過した。

## Xeno-Canto 接続

- API v3 を使用。アカウントの API キーをアプリ内で入力し、アプリ用データフォルダの
  `.xeno-canto-key` に保存する。Mac/Linux は作成時0600。Windows はユーザーフォルダの ACL に従う。
  設定 API は設定有無だけ返し、キーをログ・音源属性・検索履歴へ出さない。
  空欄で保存すると削除する。OS キーチェーンとの連携は未実装。
- 選択した種の学名・国（英語）・品質 A–E で検索する。品質は指定した評価のみで、
  「その評価以上」とは解釈しない。API 側のページ全件を表示してページ移動する。
- ユーザーが選んだ音源だけ取得し、アプリの `references/xeno-canto` に保存してから
  共通のスペクトログラムで参照区間を選択する。取得済み音源はオフラインでも使える。
  XC ID・記録者・元 URL・ライセンス・地域等を残し、参照属性として表示する。
- ダウンロードは数値の XC ID から組み立てた URL のみ。転送先は HTTPS の
  xeno-canto.org / www.xeno-canto.org に限定し、実受信量も50 MBで制限する。
  未対応の配信ホストへ転送された場合は明示エラー。検査完了前のファイルを参照登録しない。
- API のパラメータと応答項目は Echoroo full の XC API v3 実装と照合した。
  外部通信の模擬応答による契約テストに加え、2026-09-09にMac配布版の実接続を確認した。
  ユーザーが設定したキーでウグイス（Horornis diphone）・Japan・Aの51件を表示。
  選択されたXC1148086（20秒、44.1 kHz、ステレオWAV）の取得・帰属保存・
  スペクトログラム表示と、UIで選ばれた1.34〜6.79秒による実音源検索が通過した。
  解析済み2録音・720区間から上位30件を表示。これは接続・処理の確認であり、同定品質の検証ではない。

## 今回残す制限

探索用閾値・spiral plot・CSVは実装済み。判定付きの検索結果は保持するが、上位結果や
任意の類似度帯の判定だけから、不在・出現頻度・較正済み precision を算出しない。

現在は録音群内を厳密に走査する。M4 Proの年間負荷試験では210,240区間の試行検索78.33秒、
2種・各2参照区間の保存検索168.27秒。条件と容量は [測定記録](annual-benchmark-2026-09.md) を参照。
モデルは検索一括実行ごとに1回読み込み、全ファイル音声をメモリへ展開しない。
解析ジョブと検索は同時実行しない。検索のキャンセル UI は未実装。
参照音のステレオ左右選択、描画の周波数範囲／コントラスト調整、移動した元音源の再リンクは未実装。

## 確認

`apps/sidecar/test_search.py` は、実SQLite/vecを使った録音群・最新解析・モデル版の絞り込み、
自己区間の除外、複数窓の最大値、負の類似度、参照登録／認証／区間境界／音源変更、
ステレオ平均、無音補完、1 kHz純音のスペクトログラム位置を検査する。
`test_sidecar.py --real-recording …` と `scripts/check_frozen.py … --recording …` は実モデルでの検索も検査する。

M4 Pro / 24 GiB の30分実音源から360区間を解析。11:18–11:21の3秒を参照とする検索＋30秒の
スペクトログラム取得は単発確認0.78秒（モデル読み込みを含む）。最上位は8:50–8:55、類似度約0.709。
これは機能と速度の確認であり、結果の種同定や検出品質の検証ではない。

凍結版でも同じ30分音源を59.16秒で解析し、参照音登録・検索・スペクトログラム取得を0.62秒で確認、
正常終了（exit 0）。Macでは範囲ドラッグ・選択区間の再生・2/24録音への検索結果を確認した。
開発ブラウザでは検索結果の区間再生・停止、日英切り替えでの地点時刻の維持、
`koe-e-lab/sample_data/mp3/uguisu_song_01.mp3` の参照登録・検索を確認した。

`test_search_runs.py` は複数種／参照窓の最大値・負の類似度・一致した参照音、無作為抽出の
再現・母集団数、判定の追記／種ごとの分離／再起動・再解析後の保持を検査する。
XC はキー非返却、検索パラメータ、ページ末尾を欠落させないこと、帰属付き音源取得・再利用、
転送先と受信サイズの制限を模擬通信で確認した。

開発画面では実 MP3 の2区間（0–5、5–10秒）から30分録音の全360区間を検索し、
類似度0.4–1.0の該当8区間から5区間の無作為抽出、試聴・「不明」の保存・日英切替を確認した。
これは隔離した開発データでの機能確認で、鳥種の正解判定ではない。

凍結版の追加検査では、キー設定確認・30分実音源解析37.45秒・従来検索と描画0.49秒・
複数参照検索と無作為抽出・不明保存0.41秒・正常終了を確認した。
キー設定確認が音声処理モジュールを読み込んで30秒のテスト期限を超える問題を見つけ、
SciPy と音声取得処理を必要な操作時に読み込む形へ修正した。

Mac配布版でも、登録済みのウグイスMP3の0〜5秒・5〜10秒を参照に検索を保存した。
検索対象は24録音中2録音・720区間。類似度0.4〜1.0の8区間から5区間を抽出し、
先頭の朝6時録音0:30〜0:35を再生、35秒で停止してから「不明」を保存した。
検索履歴#1、抽出#1、判定#1はアプリ用DBに保持され、再起動後も参照セットが復元された。
報告#3の8根拠・不明1件と、5秒音声付きZIPまで画面操作で確認した。
この操作は動作確認であり、ウグイスの生息や品質の確認済み正例を追加したものではない。
