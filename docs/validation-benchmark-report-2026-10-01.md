> 別マシン（ToriNET リポジトリ `steps/06_echoroo_validation_benchmark/`）で実施した比較の報告を、2026-10-01 にそのまま転記した。

依頼書: `~/echoroo-validation-benchmark-handout.md`（2026-09-30）。作業記録と事前登録は [README.md](README.md)。
用語はアプリに合わせる: **正しさ**（precision）、**見つけた割合**（recall）、**声を含む区間の割合**（call density）。
区間はすべて 90% 区間。「被覆率」は 90% 区間が真の値を含んだ割合（名目 0.90）。

> 読み方: **【事実】** はこのデータで実験して確かめたこと、**【推測】** はそこからの解釈・一般化。

## 0. 結論（要約）

1. **推奨: 1 段階（日を分けない）・上位を細かく割った 6 ビン（方式 C の抽出）で 60 音、必要なら 20 音追加。** 同じ回答から
   - **声を含む区間の割合（と区間数）** はビンごとの Beta（Navine et al. 2024 / perch の式、事前分布 0.1）で出す。
     全条件で被覆率 0.87〜0.97（よくいる・中程度・珍しいのどれでも）。
   - **基準（閾値）と、その基準での正しさ・見つけた割合** は、同じ回答に床つきロジスティック曲線を当てはめ、
     「推定した正しさが 0.90 以上になる最も低い基準」を後から選んで出す（方式 E の曲線版）。正しさの被覆率は 0.93〜0.97。
     **ただし床（低スコアでの声）の事前分布は、依頼書の −4（中央値 1.8%）では珍しい種の見つけた割合を大きく過小推定する。
     床は実質なし（logit(床) ≈ −11、探索的解析）にすべき。**
2. **現行の A は推奨しない。** 見つけた割合の 90% 区間幅の中央値が 0.48〜0.91、①で基準が決まらない反復が 22〜32%、
   1 回答の反転で見つけた割合が 0.57〜0.83 以上動く反復が 1 割ある（カケスの例と同じ現象を再現）。
3. **40〜80 音では、年や種の比較に使える幅（90% 区間幅 ≤ 0.20）の「見つけた割合」は、ほとんどの種で得られない。**
   よくいる種で幅 0.25〜0.35、珍しい種では推定そのものが不安定。比較には「声を含む区間の割合」（よくいる種なら ±30% 程度）や
   同じ基準での検出数の比を使い、見つけた割合は「おおよその目安」として示すのが正直。
4. 時間帯・月の図は、**同じ基準以上の検出数（の割合）** で描く。ビンや曲線による Strategy 1 は、その種がいない時間帯にも
   0.3〜3% の値を出し（珍しい種の本当の値と同じ桁）、曲線版は全体を 5〜120% 過大にする。

## 1. 何をしたか

- データ（全区間に正解あり）
  - **Powdermill**（Chronister et al. 2021）: Zenodo 4656848 の元の 5 分 WAV 77 本（6.42 h、4 日、48 種、注釈 16,052 件。論文値と一致）。
    BirdSet の 5 s 分割版は 3 s 窓に使えないため使っていない。
  - **霞ヶ浦 2026**（`combined_ca_eval_v1`）: 496 clip（1.93 h、75 夜、10 地点、17〜07 時台）。網羅的に注釈されているのは
    対象 8 種だけ。種の確定しない `kamo` / `unknown` / `hashibiro` と重なる窓は母集団から除外（BirdNET 58 窓、Perch 49 窓）。
- モデル（アプリと同じ条件、SHA-256 はすべて一致）: BirdNET 2.4（birdnet 1.1.1, litert, 3 s 窓, シグモイド）、
  Perch V2 ONNX（32 kHz, 5 s 窓, 全クラス softmax = アプリのスコア。生ロジットも感度分析）。
  自前スコアは既存の参照スコアと一致（BirdNET 最大差 7e-4、Perch 相関 0.9998）。
- 対象種: 正例窓（少しでも重なる規則）が 10 以上の種。正例の割合で よくいる（≥5%）/ 中程度（1〜5%）/ 珍しい（<1%）。

| データ / モデル | 種 | よくいる / 中 / 珍しい | 正例の割合 | 種ごとの真の ROC-AUC 中央値（最小） |
|---|---:|---|---|---|
| Powdermill / BirdNET | 34 | 12 / 11 / 11 | 0.001〜0.63 | 0.96（0.89） |
| Powdermill / Perch | 34 | 14 / 11 / 9 | 0.002〜0.77 | 0.91（0.67） |
| 霞ヶ浦 / BirdNET | 8 | 1 / 4 / 3 | 0.006〜0.16 | 0.92（0.86） |
| 霞ヶ浦 / Perch | 7 | 2 / 4 / 1 | 0.008〜0.20 | 0.96（0.92） |

- 方式（`methods.py`。定義の詳細は README の事前登録）: A（現行）、B（4 ビン）、C（6 ビン）、D（基準起点の層＋曲線、
  床 −4 = D4 / −6 = D6）、E（1 段階・基準は後から。E-B / E-C はビンの Beta、E-Bcurve4 / E-Ccurve4 / E-Ccurve6 は曲線）。F は未実施。
- 各条件 200 回（種・回答条件・反復で固定した乱数）。n = 40 / 60 / 80 / 「60＋必要なら 20」（n=60 の recall 90% 区間幅 > 0.30 なら追加）。
  回答条件: `any`（主）、`half`（0.5 s 規則）、`boundary`（境界の音の半数を「分からない」）。Powdermill の `half` / `boundary` は n=60 のみ。
- 真値: B / C / E は全窓、A / D は「確かめる日」の窓（主）と全窓（副、表では「全窓」）。

### 3.6 そのほか

- 【事実】回答の揺れ（`boundary`、`half`）でも、推奨候補（C の density、E-Ccurve6、D6）の被覆率の変化は ±0.05 以内。
  ビンの Beta の正しさ（E-C）は −0.19〜+0.14 動くが、もともと低い（`results/pooled_metrics.csv`）。
- 【事実】Perch の softmax と生ロジットで結論は変わらない（1e-9 で丸められて同値になる窓はなかった）。
- 【事実】ビン数: C5 / C6 / C7 の density 被覆率はいずれも 0.87〜0.95。
- 【事実】ビンの Beta から補完した AUPRC は、ビン内の順序を捨てるため大きく過小（B の中程度の種で被覆率 0.005〜0.09）。
  曲線（E-Ccurve6）は よくいる種で被覆率 0.85〜0.93。ROC-AUC も同傾向。
- 【事実】D の曲線と層ごと Beta の食い違いフラグは n=60 で 0.4〜2.5%（n=40 で 5〜20%）。
- 【事実】計算時間（1 スレッド、Powdermill の最大種、80 音）: A 0.005 s、ビンの Beta 0.17〜0.29 s、D 0.33〜0.53 s、
  曲線 E 0.49〜0.75 s（`results/timing_*.csv`）。1 種 1 モデル 1 秒以内（窓 7,700 / 4,620）。
  【推測】10 万窓規模では補完（1,000 回×窓数）が比例して伸びるので、同値・近い x の窓をまとめる工夫が要る。

## 4. 考察

- **A が広い理由**【推測】: 基準未満の窓は数千あり、そこから 10〜30 音を無作為に聞くと、正例の数の超幾何区間が母集団の大きさに
  比例して広がる。見つけた割合の分母（全正例）がこの区間に支配され、1 音の差で推定が大きく動く。
  【事実】A の区間は名目以上に被覆する（0.99）が、幅が実用にならない。
- **日の分割の代償**【事実＋推測】: Powdermill は 4 日しかなく、渡りの種（例: Swainson's Thrush、Yellow-billed Cuckoo）は
  特定の日にしかいない。確かめる日に正例がない反復が多く、A / D の推定は「確かめる日」についてしか正しくない
  （全窓の真値に対する被覆率: 正しさ 0.23〜0.65、見つけた割合 0.43〜0.92）。日の分割は、月や年をまたぐ比較の土台を弱める。
- **E の楽観は小さい**【事実】: 同じデータで基準を選んでも、推定した正しさの過大は よくいる・中程度で 0.04 以下。
  【推測】①に使う 20 音を全体の推定に回したほうが得。
- **ビンの Beta で正しさを出してはいけない**【推測（機構）】: 事前分布 0.1 は低い密度の density を正しく覆うための値（Navine）で、
  上位ビンで 10 音すべて「聞こえる」と Beta(10.1, 0.1) の 5% 点が 0.94 になる。真の正しさが 0.85 でも区間外になりやすく、
  さらに「0.90 を超えたビン境界」を選ぶ選択の偏りが重なる。
- **床の事前分布**【事実＋推測】: 実データの P(声|x) は低スコアでほぼ 0。床 −4 は「最下層に多数の声がある」と仮定することになり、
  窓が数千ある最下層で幻の正例を作る → 見つけた割合の過小、density の過大、いない時間帯の値。依頼書の懸念どおり。
- **BirdNET と Perch**【事実】: 方式の順位と結論は同じ。違いは種ごとのモデルの良さ（Powdermill は BirdNET、霞ヶ浦は Perch の
  ROC-AUC が高い）で、良いモデルほど基準が見つかりやすく幅が狭い。【推測】窓の長さ（3 s / 5 s）による系統的な差は見えない。

## 5. 依頼書 §8 の問いへの答え

1. **40〜80 音で比較に使える幅の recall を出せる方式はあるか。**
   - 【事実】幅 ≤ 0.20 かつ被覆率 ≥ 0.85 を満たした種の割合は、最もよい D6（確かめる日に限る）でも よくいる種の 31%（n=60）〜45%（n=80）。
     曲線 E（床 −6）は n=60 で よくいる 7%・中程度 20%。幅 ≤ 0.30 なら n=60＋20 で よくいる 83%・中程度 53%。珍しい種はどの方式も 0%。
   - 【推測】年や種の比較に recall を使えるのは、**正例の割合 ≥ 1% かつ ROC-AUC ≥ 0.9 程度の種で、0.3 程度より大きい差だけを読む場合**に限られる。
     幅 0.2 未満には 150 音前後以上が要ると見込まれる（幅はおおむね 1/√n で、n=60 の幅 0.3 から）。
2. **基準を決める段階（①）と日の分割は必要か。** 【事実】不要で、むしろ有害。①は 22〜32% の反復で基準が決まらず、
   日の分割は推定対象を「確かめる日」に限ってしまう（全窓の真値に対する被覆率: 正しさ 0.23〜0.65、見つけた割合 0.43〜0.92）。E（1 段階）の楽観は よくいる・中程度で +0.00〜+0.04。
   【推奨】E で十分。ただし選んだ基準の真の正しさが 0.90 を下回ることは珍しくないので、画面には「推定値と範囲」を出す。
3. **B/C に曲線を足す価値、床の事前分布の影響。** 【事実】density だけならビン（B / C）が最も正直で、曲線は不要。
   一方、**基準の選択・正しさ・見つけた割合・AUPRC は曲線を足す価値がある**（正しさの被覆率: ビンの Beta 0.22〜0.77 → 曲線 0.93〜0.97。
   基準が見つかる割合: 13〜35% → 69〜91%）。床の影響は大きく、珍しい種の recall 被覆率は床 −4 で 0.39、床なしで 0.75（探索的）。
4. **BirdNET（3 秒）と Perch（5 秒）で結論は変わるか。** 【事実】変わらない（方式の順位・床の影響・日の分割の問題とも同じ）。
5. **時間帯・月の図。** 【事実】Strategy 1 はいない時間帯に 0.3〜3% を出す。基準以上の検出の割合は、いない時間帯で 0.002 以下、
   順位相関も最も高い（0.75〜0.96）。【推奨】図は **選んだ基準以上の検出数（または割合）** を描き、全体の倍率
   （推定正しさ ÷ 推定見つけた割合、とその範囲）は図の外に 1 つの数字として添える。時間帯ごとの区間は出さない
   （Strategy 1 の前提＝時間帯でスコアの意味が変わらない、は検証できないため）。
6. **推奨する方式・聞く数・見せる値。**
   - 方式: 全窓を x の分位で 6 ビン（0–50–75–87.5–93.75–96.875–100%）、各ビン 10 音（60 音）。見つけた割合の 90% 範囲の幅が 0.30 を超えたら
     各ビンに約 3 音追加（計 80 音）。日は分けない。
   - 計算: density と区間数はビンの Beta（事前分布 0.1、perch と同じ式）。基準・正しさ・見つけた割合・AUPRC は床なしの曲線
     （logit(床) を格子の下端付近に固定、例 N(−11, 0.5²)）で、正しさ ≥ 0.90 の最も低い基準を選ぶ。曲線と層の Beta が食い違えば注意を表示。
   - 画面に見せる値（大学 1 年生向けの言い方。数値は例）:
     - 「この種の声が入っていた区間は **全体の約 6%**（90% の確からしさで 4〜8%）、**約 460 区間**（330〜610）」
     - 「AIが『いる』とした区間のうち、**本当に声があったのは約 92%**（80〜98%）」
     - 「声があった区間のうち、AIが見つけたのは **約 45%**（30〜60%）。幅が大きいので、年や種の比較には使わないでください」
     - 珍しい種（推定した割合 < 1%）では見つけた割合の数字を出さず「聞いた音が少なく、見落としの程度は分かりません」と表示。
   - レポートに載せる値: 上記の推定値と 90% 区間、聞いた音の数（ビンごとの 聞こえる / 聞こえない / 分からない）、選んだ基準（スコア）、
     ROC-AUC・AUPRC（曲線から、区間つき）、曲線と層の Beta の食い違いの有無、モデル名と窓の長さ。

## 6. 限界

- 霞ヶ浦は 1.93 h・8 種で、短い clip の集まり（連続録音ではない）。夜間の水鳥に偏る。Powdermill は 4 日・夜明けのみで、
  注釈は短い chip を含まない（chip の窓は正解では「声なし」）。どちらも数万時間規模の実運用とは窓数・種構成が違う。
- 回答は正解そのもの（または境界の音の一部を「分からない」）で、人の聞き間違いは模していない。【推測】実際の誤答は被覆率をさらに下げる。
- 床の比較（3.2 節）は主結果を見た後に追加した探索的解析で、事前登録外。推奨の「床なし」はこの解析に基づくので、
  別データでの確認が望ましい。
- A の recall 区間は、層ごとの正確区間（各 95%）の端点を組み合わせた保守的な区間（同時 90% 以上）として再構成した。アプリの実装と細部が違う可能性がある。
- 「60＋20」の追加判断は各方式自身の n=60 の区間幅による。B / C は同じ回答の E-B / E-C の判定に従った。Powdermill の `half` / `boundary` は n=60 のみ。
- 種名の照合は学名と対応表（README）。日本の種では、学名を素直に照合すると Perch / BirdNET の別クラスや存在しないクラスに当たる例がある
  （ToriNET の監査 `steps/02_data_collection/data_sufficiency/results/model_mapping_audit.csv`: アオジ → *Emberiza spodocephala*、
  キジ → *Phasianus colchicus*、アマサギ → *Ardea ibis*、セグロカモメ → *Larus argentatus*、BirdNET 2.4 のシジュウカラ → *Parus minor*）。
  アプリが学名をそのまま使うと、これらの種では別の分類群のスコアを確かめることになる。霞ヶ浦の対象 8 種は問題なし。
