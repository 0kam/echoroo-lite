## 取り込み画面の再設計

### 現状の問題

- 三つの段階（場所 → フォルダ → 確認して追加）が画面上で見えない。パネルは「録音した場所」と「音声フォルダを選ぶ」の二つしかなく、確認も追加もフォルダのパネルの中に入っている。
- 「追加する録音を確認」は意味が曖昧である。「確認」が、登録の確定なのか中身の点検なのか区別できない。しかも、押さないと次へ進めない操作を利用者に一つ増やしている。
- 入力欄を少しでも変えると（`oninput`）、確認結果が黙って消える。
- 確認結果の「48 件の録音を追加します · 48:00」は「追加しました」とも読める。「48:00」の意味もわからない。0件のときに「0 件の録音を追加します」と表示し、その下で「追加できません」と言うのも矛盾している。
- 追加しないファイルを一行ずつ全部並べるため、数百行になりうる。理由ごとにまとめていない。
- タイムゾーンが自由入力（`Asia/Tokyo`）で、ラベルは「録音機で使っている時刻」である。大学1年生は IANA 名を入力できない。
- 追加した後に開く地点の画面では、「録音を解析する」が通常ボタンとして他の2つと並んでいる。次にやるべき操作だとわからない（[site-01](../output/ui-review-2026-10-01/site-01-after-import.png)）。

### 提案する流れ

**「確認」ボタンを廃止する。** フォルダを選んだら、自動で中を調べる。利用者の操作は「フォルダを選ぶ」と「追加する」の2回だけになる。ブラウザ開発時の文字入力では、Enter を押すか欄から離れたときに調べる。

段階は番号付きのカードで常に3つとも表示する（既存の `.steps` と `.step-card` を再利用する）。地点に録音を足すときは、1 を「場所：〇〇（変更なし）」の1行に縮める。

```
① 録音した場所        地点名 / 地図 / 緯度・経度 / タイムゾーン（選択式）
② 録音のフォルダ      [フォルダを選ぶ…]   選んだフォルダ：○○（[別のフォルダにする]）
③ 中身を確かめて追加  ┌ 状態の枠（高さを固定）────────────────┐
                      │ 未選択：フォルダを選ぶと、追加できる録音の数をここに表示します。│
                      │ 調査中：⟳ フォルダの中を調べています…            [中止]│
                      │ 結果  ：追加できる録音 48件（合計 48分）                │
                      │         2025/01/01 0:00 〜 2025/01/01 23:30           │
                      │         追加しないファイル 3件 ▸（理由ごとの件数）     │
                      └───────────────────────────────────────┘
                      [ 48件の録音を追加 ]  ← 主ボタン。位置と幅は固定
```

- 主ボタンは③の下に一つだけ置き、位置を変えない。ボタンを出したり消したりしないで、文言と有効・無効だけを切り替える。
  - 未選択・調査中：無効にし、すぐ下に理由を書く（例：「先にフォルダを選んでください」）。
  - 結果あり：有効にし、件数を入れた文言にする。
  - 追加中：同じボタンをスピナー表示にする（幅は変えない）。中止は状態の枠の中に置く。
  - 0件：主ボタンは無効のまま、状態の枠に理由と次の行動を書く。「別のフォルダにする」は②のリンクボタンを使う。
- 「選んだフォルダを解除」は削除し、②の「別のフォルダにする」に統合する。
- 追加しないファイルは理由ごとの件数にまとめる（例：「すでに追加済み 48件」「日時が読めない名前 2件」）。ファイル名の一覧は `details` の中に入れ、最大20件と「ほか n 件」にする。
- 全部が登録済みのときは、専用の文にする：「このフォルダの録音は、すでにこの地点に追加されています。」
- タイムゾーンは `<input list>` と `<datalist>` で `Intl.supportedValuesOf('timeZone')` を候補として出す（標準機能。依存は追加しない）。既定値は PC のタイムゾーン。
  ラベルは「録音機の時計の時間帯」、説明は「録音機の時刻を合わせた地域を選びます（日本なら Asia/Tokyo）」とする。保存方法は今と同じで、IANA 名を保存する。
- 追加が終わったら地点の画面へ移る。そこでは「録音を解析する」を主ボタンにし、「解析には 48本で約○分かかります」と書く。
  **要相談：** 主ボタンを「追加して解析を始める」にして、追加と解析を一度に行う案もある。

## 全画面の見た目のルール（既存の CSS を整える）

新しいフレームワークと依存は追加しない。`app.css` と `theme.css` のトークンを整理する。

- **余白**：4・8・12・16・24・32・48px の7段階だけを使う。パネル内は 24、パネル間は 24、ボタン間は 8、見出しと本文の間は 8 にする。`26px`、`18px`、`14px` などの半端な値はこの7段階に寄せる。
- **文字**：本文 16、補足 14、表の見出しと注記 13（これより小さくしない）、h3 18、h2 21、h1 28。現在の 10〜12px（周波数の目盛り、らせん図、`.error`）は 12〜13px 以上にする。説明文は最大 70字幅とする。
- **ボタン**：
  - 階層：主ボタン（primary）は画面の領域ごとに1つ。次が通常（枠付き）、その次が ghost とリンク。danger は削除と、その確認だけに使う。

  - 無効：`opacity` をやめる。背景 `stone-200`、文字 `stone-500`、`cursor:not-allowed` にし、なぜ押せないかを近くの1行で示す。

## スペクトログラム

### 何が変わったか（読みやすかった版との差）

- 2026-09-24（cf90452）まで：拡大できる表示は `aspect-ratio:14/3` の横長の帯で、幅 800px なら高さは約 170px だった。
- 2026-09-25（b77b5ee）：`height:clamp(240px,calc(100vh - 480px),560px)` に変わり、692c997 で `100vh - 520px` になった。画面が高いほど図も高くなる。

実装は `app.css` の3つの変数（`--spec-sm:120px; --spec-md:160px; --spec-lg:220px`）を、`AudioRegion.svelte` と `ZoomSpectrogram.svelte` から参照するだけにする。

### メル／リニアの切り替え

- 既定はメル。選択はアプリ全体で1つにし、`localStorage`（`echoroo-frequency-scale`）に保存する。言語と同じく `app.svelte.ts` の `restorePreferences` で読み込む。
- 切り替えは、周波数軸の上端に置く小さな2択（sm の segmented control）1か所だけにする。
  - 表示：「メル｜等間隔」（en：「Mel｜Linear」）。
  - `title`：「メル：低い音を広く表示します。等間隔：0〜12 kHz を同じ間隔で表示します。」（en：Mel shows low sounds larger. Linear spaces 0–12 kHz evenly.）
  - 拡大できる表示と 160px 以上の図に出す。120px の一覧には出さず、全体の設定に従う。
- 切り替えると、その画面の全ての図を再読み込みする。要求の URL に `scale` を付け、`{#key}` に含める。保存済みの拡大位置は割合で持っているので、そのまま使える。

### 軸の目盛り（API の `frequency_ticks` を使う）

- 目盛りは `frequency_ticks`（0・1・2・4・8・12 kHz、`row_fraction` は下端が0）を、`bottom: row_fraction*100%` に置いて表示する。単位「kHz」は上端に1回だけ書き、数字は「0 1 2 4 8 12」とする。リニアのときも同じ配列を使う。
- **今のコードはリニアを前提にしており、メルにすると誤った数字を出す。必ず置き換える。**
  - `AudioRegion` は中央に固定で「6 kHz」と表示している。メルの中央は約 2.3 kHz である。
  - `ZoomSpectrogram` は、表示範囲の上端と下端を `maxHz*(1-top/height)` で計算している（線形の式）。
  - 拡大時の目盛りの位置は、表示枠内の y = (1−row_fraction)×track の高さ − scrollTop で求め、枠内にあるものだけを表示する。上下端の数字表示は削除し、目盛りで代える。
- 目盛りの位置に、図の上へ 1px の薄い補助線（白の 15%）を引く。どの高さの音かを、図の上で読み取れるようにする。
