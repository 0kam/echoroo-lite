# 種ごとの確認の流れの作り直し（2026-09-30 提案）

[feedback-2026-09-30.md](feedback-2026-09-30.md) の「作業2」（検索の作り直しと声の範囲の廃止）を置き換える提案。
「合意」はユーザーと合意した事項、「提案」は未合意の案。

## 目的

調査で知りたいことは、種ごとに次の2つである。

| 知りたいこと | 何があれば言えるか | 数字 |
|---|---|---|
| いるか | 人が聞いて、1回でもその種の声だと確かめたこと | 要らない（根拠の音を残す） |
| いつ・どれくらいか | 正しさが分かっている AI の数え方 | 正しさ（①〜③） |

今の画面は、この2つを1つの流れの中で扱っているため複雑になっている。2つを分け、どの種でも同じ手順で進められるようにする。

## 合意（2026-09-30）

- 地点共通の10音と、ほかに聞こえた種の記録（声の範囲を含む）は廃止する。①〜③は種ごとに行う。
- 検索は、種を報告するためのもう1つの検出器としては扱わない。検索の基準、検索の正しさの確認、検索の図は廃止する。
- 聞いて存在を確かめた種は、出現頻度や正しさの数字なしで、「人が聞いて確認した記録」としてレポートに載せる。
- 区間は、検出の確認・種のモデルの結果・レポートが15秒、検索と種のモデルの学習が5秒のまま。
- 検索は1つの種に1つだけ。やり直すときは削除してから探し直す。

## 提案

### 1. 種のページ

種のページに2つのカードを置く。どの種でも同じ構成にする。

- ［いるか］：状態（確認できた／まだ）と、「聞いて確かめる」ボタン。
- ［いつ・どれくらいか］：モデルごとの状態（目標に届いた／届かなかった／まだ）と、「AIの数え方を確かめる」ボタン。

### 2. ［いるか］聞いて確かめる

- その種の声の可能性が高い音を、上から順に一覧にする。
  - AI が出した種：15秒区間を、BirdNET・Perch・種のモデルのスコアの高い順に交互に並べる。どのモデルが出した音かを表示する。
  - 検索した種：その種の検索結果の5秒区間を、似ている順に並べる。
- 各行にスペクトログラムと再生ボタンを付ける。ダブルクリックで、その位置から再生する。
- 押せるのは「この種の声だ」だけ（押し直せば取り消せる）。1つでも押せば「確認できた種」になり、押した音がレポートの根拠になる。
- ②③で「聞こえる」と答えた音も、同じく根拠として扱う。①の音は、AIのスコアが高い音を意図して選んだものなので含めない。

### 3. ［いつ・どれくらいか］AIの数え方を確かめる

> 2026-10-01、下の「合意（2026-10-01）」で置き換えた。

- モデルごと（BirdNET、Perch、種のモデル）に ① 基準を決める → ② 正しさ → ③ 見逃し、を行う。
- 録音を日ごとに「基準を決める用」と「確かめる用」に分ける仕組みは残す（同じ日の音で基準を決めて評価すると、結果が甘くなるため）。画面には出さない。
- ①は20音。その種・そのモデルの「基準を決める用」の15秒区間について、スコアをロジットの目盛りで最小から最大まで20等分し、各区切りから1音をランダムに選ぶ（音のない区切りの分は、ほかの区切りから補う）。答えを見て選び直すことはしない。
- 答えに曲線（スコアに対する声のある確率）を当てはめ、「その基準以上の音のうち声のある割合が90%以上」と推定される一番低い基準を選ぶ。「聞こえる」が1音もない、またはスコアと答えに対応が見られないときは「基準を決められなかった」とし、既定値は使わない。
- 同じ種の同じ15秒区間の答えは、その種のほかのモデルの①②③でも使い回す。
- ②③は現状どおり、モデルごとに固定30音。

### 4. 検索

- AI の一覧に出てこない種を探すための機能とする。
- 検索が終わったら、その種の［いるか］の一覧（検索の結果）へ移る。
- 検索を削除すると、その検索の結果に付けた「この種の声だ」と、その検索から作った種のモデルも消える。削除の前に、消えるものを示す。

### 5. 種のモデル

- 「いつ・どれくらいか」を出したい種について作る。
- 材料は、モデルを作る画面の中で、検索結果の5秒区間に「声あり／声なし」を付けて集める。この判定はモデルの材料にだけ使う。
- 作った後は、BirdNET・Perch と同じく15秒で地点の録音に当て、［いつ・どれくらいか］で確かめる。

### 6. レポート

- 種の一覧に2つの列を置く。
  - いるか：聞いて確認した（根拠の音の数）／未確認
  - いつ・どれくらいか：確かな図あり（どのモデルか）／なし
- 時間ごとの図は、モデルごとのタブで示す。

### 7. 削除

- 検索の削除（4）。
- 検出の確認の削除：種・モデルごとに、①〜③の回答を消す。
- 「この種の声だ」は一覧で取り消せる。

### 8. 廃止するもの

- 地点共通の10音、ほかに聞こえた種の記録、声の範囲（鳴き声に印を付ける）。
- 検索の基準、検索の正しさの確認、検索の渦巻きの図、「集めた似た声」タブ、上位30音を1つずつ判定する画面。
- 検出の確認と検索の判定を、モデルの材料や別の種へ使い回す仕組み。

データを移し替える処理は作らない（まだ誰もインストールしていない）。

## 決定（2026-09-30 追加）

- 検索結果の一覧で押せる操作は「この種の声だ」だけ。
- ［いるか］で見つからなかったときは、「上位○音を聞いたが確認できなかった」を記録し、レポートに残す。
- 正しさを確かめていない、または目標に届かなかったモデルの時間ごとの図も、その状態を明記してレポートに載せる。
- 種のモデルの「声なし」の材料には、②③の「聞こえない」（15秒→5秒×3）も使う（検出が不十分で、検索からモデルを作る場合を想定）。

- ①の音は、スコアの目盛りに沿って均等に固定して20音選び、答えに曲線を当てはめて基準を決める。スコアと在不在が必ずしも対応しないため、答えに応じて音を選び直す方法は採らない。

仕様に書かれていない点は、次のように決めて実装した（未合意。変える場合は相談する）。

- 曲線はスコアのロジットに対するロジスティック回帰で、20音でも「聞こえる」と「聞こえない」が完全に分かれて発散しないよう、Firthの補正を入れた。「判断できない」は当てはめに使わない。
- 「対応が見られない」は、曲線の傾きが0以下のとき（全部「聞こえる」も含む）とした。どの基準でも推定の正しさが90%に届かないときも「基準を決められなかった」とする。推定の正しさは、「基準を決める用」の日の全区間で、基準以上の区間の曲線の値を平均して求める。
- ロジットは、スコアを10⁻⁹〜1−10⁻⁹に丸めてから計算する（Perchの非常に小さい確率で目盛りが広がりすぎないため）。
- 「上位○音」の○は、一覧の上から途切れずに再生した音の数とした。記録は種・地点ごとに最新のものをレポートに載せ、検索を削除すると検索の一覧で付けた記録も消える。
- 検出の確認を削除するとき、この種のほかのモデルの確認で使っている答えは残す。
- 種のモデルの確認では、学習に使った5秒を含む15秒区間を①〜③から除く。確認前の図は、BirdNET・Perchの既定値0.1に対し、種のモデルは0.5で数え、「確かめていない」と明記する。
- 種のモデルの交差検証（参考値）は廃止した。材料は声あり・声なしが各3音以上。
- レポートから検索の参照音の章をなくした（検索は報告用の検出器ではないため）。

## 合意（2026-10-01）：AIの数え方の確かめ方を作り直す

全区間に正解がある2つのデータ（Powdermill、霞ヶ浦2026）で確かめ方を比べた
[比較報告](validation-benchmark-report-2026-10-01.md)の推奨を採用する。上の3（①〜③）と、その実装を置き換える。

- **区間はモデルの入力の長さ**（BirdNET 3秒、Perch と種のモデル 5秒）にする（2026-09-30 ユーザー指示）。
- **1段階にする。** ①（基準を決める20音）と、日を「基準を決める用」と「確かめる用」に分ける仕組みは廃止する。
- 種・モデルごとに、期間内の全区間をスコアの分位で6つのグループ（0–50–75–87.5–93.75–96.875%–100%）に分け、
  各グループから10音を無作為に選んで、**60音**を混ぜた順に聞く。グループ分けは画面に出さない。
- 60音の答えで、見つけた割合の90%範囲の幅が0.30を超えたときだけ、各グループ3音（計18音）を追加する。
- 同じ答えから次を出す。
  - **声を含む区間の割合と区間数**：グループごとの Beta 分布（事前分布 0.1、Perch の `call_density.py` と同じ式）。
  - **基準、その基準での正しさ・見つけた割合、AUPRC**：床なしの曲線（スコアのロジットに対するロジスティック曲線）を当てはめ、
    「推定した正しさが90%以上になる最も低い基準」を後から選ぶ。
  - 曲線とグループごとの Beta が食い違うときは、注意を表示する。
- **珍しい種**（推定した声を含む区間の割合が1%未満）では見つけた割合の数字を出さず、
  「聞いた音が少なく、見落としの程度は分かりません」と表示する。
- **時間帯・月の図**は、選んだ基準以上の検出数（割合）で描く。全体の補正の倍率（推定した正しさ ÷ 推定した見つけた割合）は、
  図の外に1つの数字として添える。時間帯ごとの範囲は出さない。
- **モデル間の種の対応**（シジュウカラ、キジ、アマサギ、セグロカモメ、アオジなど）は、別の作業として整える。

## 実装の方針（2026-10-01、細部は未合意）

上の合意を実装するときに、次のように決める。変える場合は相談する。

- 区間をモデルの入力の長さにそろえるのは、確かめる作業だけでなく［いるか］の一覧・レポート・CSV も同じにする
  （基準はその長さのスコアで決まるため、図も同じ長さで数える）。検索と種のモデルの学習は5秒のまま。アプリから「15秒」はなくなる。
- 答えは「種・録音・区間の始まりと終わり」ごとに1つ。区間が同じ Perch と種のモデルの確認では答えを使い回す。BirdNET（3秒）とは共有しない。
- 確かめる作業で「聞こえる」と答えた音は、すべて［いるか］の根拠にする。
- 種のモデルの「声なし」の材料には、5秒区間の「聞こえない」だけを使う（3秒の答えは使わない）。
- 「判断できない」は推定に使わず、その数を表示する。
- 結果は60音（追加した場合はその分も）を聞き終えてから表示する。途中の答えで数字を見せない。
- 基準が決まらないとき（どの基準でも推定した正しさが90%に届かない）も、声を含む区間の割合は出す。
  図は既定の基準（BirdNET・Perch 0.1、種のモデル 0.5）で描き、「基準を決められなかった」と明記する。
- モデルごとの状態は、まだ／途中／基準が決まった／基準を決められなかった、とする（「目標に届いた・届かなかった」はなくす）。
- 曲線の計算：P(声|x) = expit(a + b·(x − x₀))。x はスコアのロジット、x₀ は最上位グループの下限。
  a ~ N(0, 2.5²)、b > 0 で half-N(1.5)、床は expit(−11) に固定（報告の「実質床なし」）。格子で事後分布を求め、
  聞いていない区間に声の有無を1,000回割り当てて範囲を出す。区間が多いときは、x の近い区間をまとめて計算する。
- 古いデータの移し替えはしない（データの版を上げ、古いデータは開けないと表示する）。

## 実装（2026-10-01）

上の合意と実装方針を sidecar に実装した。BirdNET は3秒、Perch・種のモデルは5秒の区間を、候補一覧、確認、集計、図、CSV、根拠音で一貫して使う。保存データは schema version 2 とし、回答のキーを「種・録音・開始秒・終了秒」にした。旧①②③、日分割、Firth 回帰、固定30音の評価、再現率の別段階、片側95%下限による目標判定は削除した。

確認は `stratified_quantile6_v1` の1段階である。全区間を順位分位の6群に分けて各群10音（群が小さい場合は全音）を固定し、回答順も保存する。全回答後だけ、ビン別 Beta(0.1, 0.1) の10,000回抽出による声を含む割合・区間数と、床を `expit(-11)` に固定した格子事後分布・1,000回の有限母集団予測による基準、正しさ、見つけた割合、AUPRC、補正倍率を返す。大きな母集団は同じスコアを分割しない最大2,000群へまとめる。珍しい種の規則、推定方法間の食い違い、追加18音にも対応した。

UI が使う HTTP API は次のとおり。

- `POST /validations`: `dataset_id`, `species_id`, `start_date`, `end_date`, `model`（`birdnet` / `perch` / `custom`）、種のモデルだけ `model_id` を送る。同じ適用可能な確認があれば再開し、なければ作成する。
- `GET /validations/{id}`: 確認画面用。`status`（`in_progress` / `decided` / `undecided` / `stale`）、`counts`（全体と6群の `total`, `answered`, `heard`, `not_heard`, `unknown`）、`question`（`id`, `source`, `start_s`, `end_s`, `version`, `review_position`, `review_total`）、`history`、`window_s`, `population`, `can_extend`, `extended` を返す。未開始は種詳細の各 check で `status: not_started` とする。
- `POST /validations/{id}/answers`: `item_id`, `verdict`（`target` / `other` / `unknown`）、任意の `version`, `examples_snapshot` を送る。未回答は保存順に答え、回答済み項目は同じ API で修正できる。途中の `results` は空である。
- `POST /validations/{id}/extend`: `can_extend` が true の完了済み確認に限り、各群3音を追加する。開始後は全追加回答が終わるまで `results` を空にする。追加しない場合は、そのまま完了結果を使う。
- `POST /validations/{id}/delete`: 同じ種の別確認が同一区間を使っていない回答も含めて削除する。

完了後の `results[engine]` は `status`, `threshold`, `reason`, `density`, `count`, `precision`, `recall`, `recall_status`, `auprc`, `multiplier`, `answers_per_bin`, `unknown`, `disagreement`, `curve_density`, `posterior_edge_mass`, `grid_edge_ok`, `model_sha256` を返す。各推定値は原則 `value`, `low`, `high`（中央値または指定された点推定、90%範囲）を持つ。再現用に確認本体へ `method`, `seeds`, `quantile_bounds`, `bin_bounds`, `bin_weights`, `population`, `window_s`, `models`, `priors`, `grid`, `draws` を保存する。基準未決定または未確認の図は BirdNET・Perch 0.1、種のモデル0.5で集計し、その状態を併記する。

未合意として実装時に決めた細部は次のとおり。

- 分位境界の整数化は `floor(q × N)` とし、同点は保存 seed の無作為順で分ける。
- ある群の回答がすべて「判断できない」の場合、その群の声を含む割合の点推定は対称な Beta(0.1, 0.1) 事前分布の平均0.5とする。
- 追加時に未確認区間が3音未満の群は、残っている区間をすべて追加する。どの群にも未確認区間がなければ追加を提示しない。
- 最大2,000群への集約では、同点スコアを分割せず、異なるスコア値を昇順にほぼ同数の群へ分ける。群内の曲線計算にはロジットスコアの平均、基準候補には群の最小スコアを使う。
