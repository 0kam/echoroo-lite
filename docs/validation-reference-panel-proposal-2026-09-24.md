# 検証中に「お手本の声」を参照できるようにする提案（2026-09-24）

状態：2026-09-24 にユーザーと合意（下記「決定」）。Opusで実装中。

## 課題

検証（AIの検出が正しいか人が答える作業）は、レポートの信頼性を担保する最も重要な工程であり、
最も負荷が高い。実機で試したユーザー自身が「鳴き声が区別できず諦めた」。
現在の検証画面には、対象種の声がどんな音かをその場で確かめる手段がない。
「この種の声を練習」は同梱クイズ（26種）へ飛ぶが、この地点の検出60種のうちクイズにあるのは8種で、
検証対象になる上位種（ルリビタキ、メボソムシクイ、オオムシクイ、エゾムシクイ、フクロウ）は含まれない。

目標：「うっすら鳥は好きだが声はぼんやり」の担当者が、声を覚えながら検証を進められること。
なめらかさを妥当性と同じ重さで扱う。

## 提案の中心：お手本パネル

検証画面と検索の判定画面に、問題の音と並べて「この種のお手本」を置く。
お手本は同じスペクトログラム設定・同じ時間幅で表示し、形を見比べられるようにする。

### お手本の出どころと表示順

| 順 | 出どころ | 表示ラベル | 備考 |
|---|---|---|---|
| 1 | 名前が確かな音：同梱クイズ素材、Xeno-Cantoから取得した音、検索に使ったお手本 | 「名前が確かな音 · XC123456 · 録音者 · CC BY-NC-SA」 | 出典と利用条件を表示。既存の `audio_references` を再利用 |
| 2 | 利用者がこの地点で「聞こえる」と答えた音、範囲を選んだ音 | 「あなたが確認した音 · 2024/08/08 7:01」 | 同じ録音機・同じ環境なので最も似ている。回答が増えるほど増える |
| 3 | この地点でAIが最も確信した音 | 「AIが最も確信した音（人は未確認）」 | 1・2が無いときの補助。既存の「検出した音を聞く」の上位区間を再利用 |

### 妥当性を保つための条件

- 問題の音そのものに対するAIのスコア・抽出理由は今までどおり見せない。
- 出どころ3（AIが確信した音）からは、その検証で出題される全項目（調整・評価・見逃し）を除外する。
  出題項目に対するAIの判断を間接的に知らせないため。検索の判定でも、抽出中の項目を除外する。
- 出どころ3は「人は未確認」と必ず明記し、出どころ1・2があるときは後ろに置く。
  精度が低い種（例：ウグイス10%）ではAIの確信音自体が誤りである可能性があるため。
- 出どころ2は利用者自身の判断に基づく循環がある。出典が確かな音（1）を先に置き、ラベルで区別する。
- 回答時に、利用できたお手本の一覧（出どころ・ID）を回答記録に保存する。
  クイズ成績を回答時点で保存している現行の仕組み（`quiz_snapshot`）と同じ扱い。レポートの再現性を保つ。

### 画面の流れ

1. **始める前（「確認を始める」画面）**
   - 対象種のお手本を2〜3件表示し、「まず声を聞いてみましょう（1分）」と促す。任意。
   - お手本が無い種には「Xeno-Cantoからお手本を用意する」を1ボタンで用意する
     （既存の検索条件の既定値：国 Japan・明瞭さ A、上位3件を取得してローカル保存。以後はオフラインで使える）。
     APIキー未設定・オフラインのときは、その旨と「検索でお手本を追加」への案内を出す。
   - 複数種をまとめて評価する場合は、種ごとに1件ずつ並べて「聞き比べ」にする。
2. **回答中**
   - 左：問題の音（現状どおり）。右：お手本1件と「次のお手本」。出どころラベル付き。
   - 主操作は「聞こえる／聞こえない／判断できない」の3択。範囲指定は「聞こえる」を選んだ後の任意操作にする
     （既存レビュー A5）。
   - 「判断できない」は誤りではなく保留として扱うことを、ボタン近くに一言で示す。
3. **回答後**
   - 「聞こえる」と答えた音は、次の問題から出どころ2のお手本として使える。
     利用者は自分の判断を積み重ねながら耳を作る。

### やらないこと（今回）

- 似た種の自動提示（ムシクイ類の聞き比べ）は、まとめて評価する種の並列表示で代替する。
- お手本の再生回数による回答の重み付けや補正はしない。
- 新しい依存関係は追加しない。表示は既存の `AudioRegion`、取得は既存のXC取得APIを使う。

## 実装の範囲（見積り）

- sidecar：`GET /species/{id}/examples?dataset_id=&validation_id=|run_id=` を追加。
  出どころ1〜3を集めて返す。出題項目の除外はここで行う。
  XCの「お手本を用意する」は既存の search + import を1回で呼ぶ薄いエンドポイント。
  回答の保存に `examples_snapshot` を追加。
- web：`ReferencePanel.svelte` を新設し、検証画面・検索の判定画面・開始画面に置く。
  「この種の声を練習」はクイズに種があるときだけ表示し、無いときは `wPracticeMissing` を使う。
- レポート：回答時のお手本一覧を `validation/` の保存記録に含める。本文の変更は最小。

## 決定（2026-09-24、ユーザー）

1. 出どころ3（AIが最も確信した音）は今回は含めない。出どころは1・2のみ。
2. XCの1ボタン取得の既定値（国 Japan・明瞭さ A・3件）で進める。
3. お手本は回答中も常時表示し、必要に応じて別ウィンドウで開く。
4. 追加：その鳥のイメージが湧く情報へ、その場からアクセスできるようにする。
   「街中に超希少種」「高山帯に海鳥」のような明らかな不整合に利用者が自分で気づけるようにする。
   eBirdの種ページ（日本語表示。写真・生息環境の説明・分布図・音声がある）を既定のブラウザで開く。
   eBirdの種コードは eBird Taxonomy v2025（Cornell Lab、要引用）の学名→コード対応を同梱して引く。
   コードが無い種は Wikipedia（日本語UIでは和名、英語UIでは学名）へのリンクで代替する。
   外部ページは Tauri の opener プラグインで既定のブラウザに開く（対象ドメインを限定）。
