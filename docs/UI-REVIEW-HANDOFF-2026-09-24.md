# Claude向けUIレビュー引き継ぎ

## 対象

今回mainに取り込む現行実装をレビューする。旧 `.claude/worktrees/ui-ux-redesign-e4867a` は過去の作業が残っているため、今回の起点にしない。未コミットの旧作業を削除・上書きせず、最新mainから別ブランチを作る。

目的は、非専門家が地点の音源を解析し、検出・検索・検証の根拠と不確かさを伴う生物多様性レポートを作れること。画面の機能数を増やすより、各ページの主目的、平易な日本語、戻り先、作業の保存を優先する。

先に `AGENTS.md`、`docs/requirements.md`、`docs/ux-direction-2026-09.md`、`docs/ux-checklist-2026-09.md` を読む。要件を変更する提案と、既存要件内のUI改善を区別する。

## 起動

依存関係の準備とMacデスクトップ起動はREADMEを参照。ブラウザで試す場合は、実利用データとは別の保存先を使う。以下のディレクトリは再実行時には既存データを保持する。

```sh
.venv/bin/python apps/sidecar/server.py --data .local-data/claude-ui-review --models poc/models
```

別ターミナルで `npm run dev`。sidecarの起動行に表示されるURLとtokenを使い、Viteの表示したURLに `?url=<sidecar URL>&token=<token>` を付ける。アプリ内の画面遷移はハッシュルーティング。tokenやXCキーをコミットしない。

## 優先して確認する工程

1. 地点作成／再利用 → 録音取り込み → 解析 → 結果全体 → 種の詳細 → 結果へ戻る。
2. 一覧にない種を名前で探す → 参照音を複数追加 → 検索 → 音を聴いて判別 → 結果へ戻る。
3. 15秒の音を聴き、範囲と種を指定 → 保存 → 訂正 → 中断／再開。拡大・移動・ダブルクリック再生も確認する。
4. 検出条件の調整 → 検出の確かさの評価 → 必要に応じて見逃しの評価。途中・完了・目標未達の違いが説明なしで伝わるか。
5. 独自モデル作成 → 結果 → 評価。学習時の参考値と、別の録音での評価が混同されないか。
6. HTMLレポート作成 → 図表・音源・検証結果を確認。クイズを開始・終了して戻る。全工程を日本語／英語で確認する。

現行の新規評価は、種・モデルごとに固定した最大30音を評価し、片側95%信頼下限が80%以上かを判定する。音は種・モデル間で共用し、回答済みの内容を再利用する。調整の目標90%と評価の目標80%は役割が異なる。未回答・判断不能を勝手に陰性へ変えない。未達でも結果を表示する。詳細は `docs/validation-design.md`。

## 検証済み範囲と限界

Macとブラウザでの最新記録は `docs/validation-effort-qa-2026-09-24.md`、モデル作成を含む記録は `docs/release-readiness-2026-09-22.md`。BirdNET予測による代用回答は機能試験用であり、生物学的な正解や独立した性能評価ではない。操作ツールの時間を人の聴取・判断時間として扱わない。

今回の機能追加後のWindows確認は未実施。以前のWindows成功記録と区別する。生成済みのレポート、試験音声、実行ログはローカルの `.local-data/`・`output/` にありGitには含まれない。必要な確認用データと出力はレビュー環境で用意する。

修正後はPythonテスト、`npm run check`、`npm run build` と変更箇所の実操作を確認する。レビュー結果には画面・再現手順・ユーザーへの影響・最小の改善案を記録する。
