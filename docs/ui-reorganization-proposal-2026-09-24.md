# 作業の道筋を一本にする整理案（2026-09-24）

状態：2026-09-24 に全項目をユーザーが承認（判断1〜4すべて提案どおり）。Opusで実装中。

## 何が錯綜しているか（実装の事実）

人が音を聞いて答える作業が、入口も名前も違う4系統に分かれている。

| 入口 | 画面 | 中身 |
|---|---|---|
| 地点の結果「録音を聴いて確かめる」 | 聞こえた生き物を選ぶ | 地点から無作為に抜いた15秒を聞き、**全種**について名前と範囲を付ける。10音で「聞こえた生き物」一覧へ |
| 聞こえた生き物「選んだ生き物の検出を確かめる」 | 60種のチェックボックス | 選んだ種の検証を作る。複数選ぶと「まとめて評価」。条件によっては「まとめられない」で拒否 |
| 種ページ「結果の確かさを調べる」 | 上と同じ「聞こえた生き物」一覧へ飛ぶ | 実体は同じ検証。入口の名前だけ違う |
| 種ページ「参照音による検索」→ 判定 | 似た音を一つずつ | 検索の判定。別の3択画面 |

さらに「この種の声を見分けるモデルを作る」は、材料の出どころも次に何が起きるかも見せずに即実行し、
作ったものを消せない。旧方式の検証（目標90%）と新方式（目標80%）の文言も併存している。

## 整理の原則

- 人が音を聞く作業は**1種類の画面**（3択＋お手本）だけにする。名前は「聞いて確かめる」。
- 入口は種ページの1ボタンだけ。地点全体の聞き取り、種の複数選択、まとめて評価は利用者向けから外す。
- 内部の共通標本（無作為10音）は残す。利用者には「最初の10音」としてその種について答えてもらうだけ。
  同じ音が別の種でも出るが、画面上は「その種を聞く」以外の説明を要求しない。
- モデル作成は「材料を見せる → 作る → 確かめる → 消せる」の独立した画面にする。

## 利用者が見る道筋

```
地点の結果（種一覧：確認できた／確認が必要／検出が少ない）
  └ 種の結果
      ├ 聞いて確かめる ……… 3択＋お手本。①最初の10音 → ②この種の音 最大30（AIごと） → ③任意：見逃し
      ├ お手本から探す ……… XC／PCの声で検索 → 似た音を「聞いて確かめる」（同じ画面）
      └ この地点の声でAIを作り直す（条件を満たしたときだけ表示）
            材料の一覧 → 作る → 30音で確かめる（同じ画面） → 結果 → 削除
  └ レポートを書き出す（既定は「確認できた」種と「確認が必要」種。「検出が少ない」種は明示選択）
```

## 削除・統合するもの

| 対象 | 扱い | 失うもの・代替 |
|---|---|---|
| 「録音を聴いて確かめる」（地点全体の聞き取り画面） | 利用者向けから削除。共通標本の作成はサーバー内部に残す | 無作為な音でAIが検出しない種を見つける経路。代替は「お手本から探す」 |
| 「聞こえた生き物」一覧・60種チェックボックス | 削除 | なし（種ページから直接入る） |
| まとめて評価（複数種同時、`validation_groups`） | 削除。既存のまとめて評価は個別の検証として表示 | 同じ音を1回聞いて複数種に答える効率。1種ずつ聞く方が迷わない |
| 「結果の確かさを調べる」「検証の結果」「確認を続ける」等のボタン名 | 「聞いて確かめる」「続きを聞く（12/30）」「結果を見る」に統一 | — |
| 旧方式（目標90%）の固定文言 | 検証ごとの目標値から生成 | — |
| 「この種の声を見分けるモデルを作る」ボタン（常時表示） | 材料が足りるときだけ表示し、独立画面へ | — |

## モデル作成画面（新設）

見出し：「この地点の声でAIを作り直す」。入口の条件：この種の「聞こえる」が3音以上、「聞こえない」が3音以上。

1. **材料**：正例・負例の一覧（聞くボタン付き、出どころ：聞いて確かめた音／検索で判定した音）。
   印が無い「聞こえる」15秒の音は「印が必要な音：N件 → 印を付ける」として作業に変える。
   （現状はこの音が黙って捨てられている。範囲の印付けは、この画面でだけ意味を持つ操作にする）
2. **説明**：「これらの音でAIを作り、この地点の全録音に適用します。作った後、別の録音30音で正確さを確かめます。」
3. **作る** → 進捗 → **結果**：適用後の検出数、次の作業「30音で確かめる」。作成に使った音での参考値は折りたたみ。
4. **削除**：作成物（モデルファイル・スコア・そのモデルの検証）だけを消す。元の回答は残す。APIを新設する。
5. 作ったモデルは種ページのタブに「作り直したAI（9/24作成）」として並ぶ。

## 実装の順序（各段階で実画面を確認）

1. 入口の一本化と削除：種ページ →「聞いて確かめる」で直接開始。地点全体の聞き取り画面・一覧・まとめて評価を削除。
   ボタン名と状態表示を統一。目標値の固定文言を廃止。
2. モデル作成画面と削除API。印付けをこの画面の作業に移す（検証画面の「任意の印付け」は外す）。
3. 地点の結果の3区分と次の一手、レポートの既定選択（前回レビューのC1-1, 2, 5）。

## 判断をお願いしたい点

1. 地点全体の聞き取り（無作為な音に全種の名前を付ける作業）を利用者向けから外してよいか。
   「AIが検出しない種」は検索に一本化する。
2. まとめて評価（複数種同時）を削除してよいか。
3. 印の無い「聞こえる」15秒音の扱い。提案は「モデル作成画面で印を付ける作業にする」。
   代替案は「15秒の中でPerchの最高スコアの5秒を正例にする」（弱いラベル、作業は不要）。
4. モデルの削除を追加してよいか（作成物のみ削除、回答は残す）。
