# Mac の画面応答・性能確認（2026-09-10）

## 対象と測り方

- M4 Pro の Mac。日本語の全18種類のルートと、再生・回答・戻る操作を確認する。
- 通常サイズはテスト用カタログのコピー（主地点25録音、12時間、2録音を解析済み）。実際の利用者のクイズ成績・検証回答は変更しない。
- 大規模ケースは既存の17,520録音・292時間・35,040解析のベンチマーク。実音声を繰り返した負荷試験用データであり、1年間の生態学的観測結果ではない。今回はモデルの年間再解析を実施していない。
- APIは配布用の凍結バイナリを起動し、同じ要求を3回測る。UIはCUAで実際に操作する。操作ツールが画面遷移後も待つ時間を含むため、UI測定は表示待ちの上限値。API応答と描画・操作の時間を混同しない。
- 普段の画面移動は約1秒、初回の図は約2秒を目安にする。解析・検索・旧データの初回集計は別の長い処理として扱い、進行中の表示と中断・移動の可否も確認する。これらは開発上の目安であり、利用者テストで確定した許容時間ではない。
- 開発ブラウザで観測した約3.05秒の移動には、操作ツールのクリック完了待ちが含まれる。クリック処理に3.283秒、移動後の要素確認に0.010秒というケースを確認した。これをアプリが常に3秒止まる証拠とはしない。

## 見つかった問題と修正

1. クイズから戻ると、親画面が破棄済みの音声部品を再度停止し、nullのaudio要素で例外になっていた。親の二重終了処理を削除し、共有部品の停止を繰り返し呼べるようにした。再生準備中のイベント解除は元の音声要素を保持して行う。
2. スペクトログラムの初回表示は42.761秒、同じ要求の2回目は0.052秒だった。凍結版のimport-time計測でscipy.signalの読み込みが42.701秒を占めた。表示は元のサンプリング周波数でNumPy FFTを使用する。32msの窓・8msの間隔、最大12kHz・1000列、短い音を失わない最大値集約を保つ。FFTは256窓ずつ処理して作業メモリを抑える。解析・検索・書き出し用の32kHz変換は従来どおり。
3. 検証の最後の回答は、統計ライブラリの初回読み込みを伴うと41.272秒かかった。超幾何分布の両側区間は同じ式のまま、標準ライブラリmath.combによる整数の組合せ数で裾確率を求める。各層の標本は最大60なので、和の項数は最大61。推定方式・目標precision・未知回答の扱いを変えない。
4. 画面を戻るたびに、年35,040件の解析メタデータを読み直してハッシュを作っていた。SQLiteの変更トリガーで更新を追い、変更時だけ作り直す。録音の存在・サイズ・更新時刻の確認はキャッシュ利用前にも必ず行う。種一覧そのものも既存の保存キャッシュを使う。
5. 新しい種を開くたびに、数万個の圧縮ファイルを開いていた。表示用の配列を256録音ずつまとめた再生成可能なキャッシュを用意し、種の結果と検証の音声抽出で共有する。地域別の種一覧、欠けた解析区間、スコアと根拠区間を保持する。
6. 解析の最後に「結果を表示する準備」を行い、種一覧と共有キャッシュの準備が済んでから「完了」にする。旧解析データの最初の集計費用を、普段の画面往復の時間と区別する。

NumPyの描画処理では、画素ごとの小さな配列生成も除去した。新しい依存ライブラリは追加していない。

統計式の参照：[SciPy hypergeom の定義](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.hypergeom.html)。配布方法も一時的に比較したが、初回はonedirでも23.173秒だったため、配布構成を増やす変更は採用していない。[PyInstallerの配布方式](https://pyinstaller.org/en/stable/usage.html)

## 再実行

```bash
.venv/bin/python -m unittest discover -s apps/sidecar -p 'test_*.py'
npm run check
.venv/bin/python scripts/benchmark_views.py \
  apps/desktop/binaries/echoroo-sidecar-aarch64-apple-darwin \
  --source-data <既存のデータフォルダ> \
  --output <新しい測定フォルダ> --models poc/models
```

`measurements.json`に起動・初回・再訪の秒数と応答バイト数を保存する。接続トークンは記録しない。コピー元の音源・解析ファイルを参照するため、表示用の派生ファイルがない場合は再生成される。

- 初回と再訪を分ける。測定中にモデル解析やビルドを同時実行していないことを記録する。
- ローカルAPIの時間だけでUI合格としない。読み込み表示が消え、図・選択肢が操作できるまで見る。
- クイズで「開始→戻る→再開」を繰り返す。再生準備中、再生中、回答後、復習再生中からも戻る。
- エラーが出ていないことと、前画面の音が残っていないことを確かめる。
- 検証の最後の回答まで含める。通常画面では使わない遅延読み込みを取りこぼさない。
- 言語を切り替え、同じ対象・回答数・録音時刻が保たれることを見る。
- 種名・録音・モデル出力が変わったときは更新され、元音声の変更・消失はキャッシュで隠れないことを確認する。
- 更新する凍結バイナリをテストプロセスが直接実行中なら、終了してから再ビルドする。実行中ファイルを上書きすると遅延importが壊れ、アプリ由来でない接続エラーになる。
