## 作るもの

| OS | 形式 | 作る場所 | 備考 |
|---|---|---|---|
| Windows 10/11（x64） | インストーラ（NSIS の `.exe`） | GitHub Actions `windows-latest` | MSI は作らない（1形式に絞る）。WebView2 は同梱の起動用プログラムで、なければ入れる |
| macOS 12 以降（Apple Silicon） | `.dmg` | GitHub Actions `macos-14` | Intel Mac は対象外（必要になったら追加） |
| Linux（x64） | `.AppImage` と `.deb` | GitHub Actions `ubuntu-22.04` | 古めの Ubuntu で作り、新しい配布物でも動くようにする。音声の再生に GStreamer が要る |

- 1つのワークフロー `release.yml` を、`v` で始まるタグを押したときに3つの OS で同時に動かし、下書きの GitHub Release に置く。
- 各 OS で、テスト → 画面のビルド → サイドカーの固め → 固めたサイドカーの動作確認（解析・検索・レポート・クイズ）→ インストーラ作成、の順。
- 既存の `desktop.yml` は main への push でも動かし、main がいつも Windows で通ることを確かめる。

## 判断が必要な点

1. **配布の場所**：リポジトリは非公開なので、そのままでは利用者がダウンロードできない。
   - 案A：配布専用の公開リポジトリを作り、そこの Releases に置く（ソースは非公開のまま）。
   - 案B：本体のリポジトリを公開する。
   - 案C：所属機関のウェブサイトなど、別の場所に置く。
2. **Mac の署名と公証**：署名していないアプリは、最近の macOS ではダウンロード後に「開けません」と出て、
   システム設定から許可しないと起動できない。非専門家には難しい。
   Apple Developer Program（年額 約1.5万円）に登録し、Developer ID で署名・公証することを勧める。必要なものは証明書と App 用パスワード（GitHub の Secrets に保存）。
3. **Windows の署名**：署名していないと「WindowsによってPCが保護されました」と出て、「詳細情報 → 実行」が必要になる。
   - 初回は署名なし＋手順の案内で出す（費用なし）。
   - または Azure Trusted Signing（月額 約1,500円、組織の確認が必要）などで署名する。
4. **公開する版**：標準版（Perch のみ）は3つの OS で公開する。BirdNET 付き版（非商用）を一般に公開するか、
   展示・研究用に限るか。企業の環境部署での実務利用は、BirdNET の非商用条件に当たる可能性がある（[モデルの出典](model-sources.md)）。
5. **最初の版番号**：例 0.9.0（試用版）または 1.0.0。

## 判断なしで進めること

1. Mac（このマシン）でサイドカーを固め、標準版の `.dmg` を作って起動・解析まで確かめる。
2. `release.yml` を作り、署名なしで3つの OS のインストーラを作れるところまで通す（非公開のまま、Actions の成果物として保存）。
3. `desktop.yml` を main への push でも動くようにし、今の main を Windows で確かめる。
4. Linux の音声再生（GStreamer）と、AppImage にメディア関連を含める設定を確かめる。
5. 各 OS のインストール手順（署名なしの場合の警告への対処を含む）を README に書く。

## 未確認・リスク

- Mac で署名するとき、PyInstaller の1ファイル形式のサイドカーは、実行時に一時フォルダへ展開するため、
  ハードンドランタイムの例外設定（entitlements）が要る可能性がある。署名の方針が決まったら確かめる。
- Linux の AppImage は WebKitGTK とメディア関連の同梱で大きくなり、配布物によって再生できないことがある。`.deb` を主にする。
- 11/28 の展示は Windows。Windows の確認を最優先にする。
