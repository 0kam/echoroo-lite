# 富士の全区間注釈データによる精度確認方式の比較（2026-10-29）

本書は将来の変更を決めるための評価実験である。方式の採用は未合意。
`apps/` は変更せず、学習・コミットは行わない。検出数を補正する倍率は出さない。

**【事実】** は今回のデータ・コードで確認した結果、**【推測】** はその解釈、
**【比較上の解釈】** は元の提案で未指定だった箇所を埋める実験上の規則を示す。

## 1. 比較条件

- 評価専用の富士データ：60クリップ、各36窓、計2,160窓。1窓5秒、開始0秒、5秒刻み。
  音声全体はアプリ同様に読み込み・リサンプルし、端数を含めて推論するが、評価には完全な36窓だけを使う。
- `analysis.load_onnx`・`analysis.infer_onnx`・`audio.resample` を直接呼ぶ。
  Perch V2 は14,795クラス全体への float64 softmax 後に対象列を取り出す
  （`reports.read_classification_windows` と同じ順序）。Kinglet-B v0.2.0 は
  アプリの318出力への softmax 後、背景を落とした317種の確率をそのまま使う。
- Perch はアプリの `species.ebird_codes`・`analysis.perch_label_index`、Kinglet は
  `classes.csv` の `ebird_code` で対応付ける。42コードすべてが両モデルに対応する。
  データ・音声・モデル・ラベル・対応表・推論コードの SHA-256 とバージョンは結果JSONに保存する。
- 正例は `windows.labels` にコードを含む窓。`mask` はその種だけを除外する。
  `unknown=True` の626窓は全種で除外する。これは以前の比較の「不明音と重なる窓を除外」に合わせた保守的な規則であり、

- 有効母集団は種ごとに異なる。正例5窓以上の38種を各モデルで比較する
  （多い：≥5% 14種、中程度：1%以上5%未満14種、珍しい：<1% 10種）。
  除外種は `eurbul` 1窓、`eurjay1` 3窓、`eurnut2` 2窓、`grywag` 4窓。

  方式間で seed と窓全体への回答を共有する。スコア同値の順位だけは seed で無作為化する。

### G・A1 の未指定部分をどう解釈したか

**【比較上の解釈】** 以下は採用決定ではなく、今回の再現可能な定義である。

1. A1 の残り5層は現行の下位5層の相対幅を保存する。
   境界は `[0,.5,.75,.875,.9375,.96875]/.96875`。検出ゼロでも最上位層を空にし、
   曲線の中心だけは `logit(0.1)` とする。それ以外の中心は最上位層の最低スコア。
2. G の `m` は除外後の検出数。D三分位は `numpy.array_split`、
   `k=max(m,25)`、B1は次のk窓、B2はその次の4k窓、B3は残り。小さい層は全数。
3. CP1 は precision@0.1 の両側95%区間が0.90を跨がなければ、**上下どちら側でも終了**する。
   下側で停止しても、D内に中央値precision≥0.90の境界があればそれを選ぶ。なければ未決で終了する。
   検出ゼロではCP1を使わず、B層まで進む。
4. CP2直前に precision@0.1 の両側95%区間が0.90を跨ぐ場合だけD各層に未抽出窓を最大4追加する。
   延長は1回。延長前は終了判定をせず、延長後をCP2とする。全数回答済みの層に不明回答があっても再質問しない。
5. 各CPの誤差配分は0.05+0.05。停止判断用は各95%、報告・被覆率比較用は各90%区間。
   **事後区間へのBonferroni配分だけでは、データから選んだ閾値の頻度論的被覆は保証されない。**
   その妥当性を今回の実測で調べる。延長前後の条件付けにも一律の保証は置かない。
6. 各層で `p~Beta(y+.5,n-y+.5)`、`T=y+Binomial(N-n,p)` を10,000回。
   不明回答は未観測として残す。既知の全数回答なら分散ゼロ。
   閾値候補は回答済み範囲の層境界（Dの末尾は0.1）で、累積precision中央値≥0.90の最小スコアを選ぶ。
   スコア同値を途中で切る境界は選ばない。CP1では未回答B層へ外挿しない。補間曲線は使わない。
7. B1の95%上限は上記予測の95百分位を整数に切り上げる。`3N/n` 近似は使わない。
   **CP1終了ならB1上限は未評価**。報告できたCP2だけの被覆率と、その報告率を別々に示す。
   停止による選択の影響を切り分けるため、全反復で事前に固定したB1標本の上限も裏で評価する
   （shadow）。この回答は停止・閾値・実回答数に使わない。
   B3は設計に基づく評価不能とし、見逃し全体の上限やrecallの保証へ読み替えない。
   区切りを0.1より上げた場合、D内で除外された正例もB1上限には含まれない。

## 2. 指標と検査

標本に含まれる真陽性3窓以上の率、既知の「対象あり」回答3件以上の率、区切り未決率、
選んだ区切りでの真precisionを90%区間が含む率、precisionの絶対誤差中央値、回答数中央値を記録する。
precisionが定義できる反復だけで被覆率・誤差を計算し、その分母もJSONに残す。
未決を除外した被覆率だけで良否を判断しない。

表の率は種を等しい重みで平均する。誤差・回答数は**種ごとの中央値の平均**であり、
全種をまとめた中央値ではない。JSONには各種の値も収録する。
200反復の種別率は、真の率が50%付近ならモンテカルロ標準誤差が約3.5ポイントある。
反復は同じ録音集合からの再抽出であり、38種×200件を独立した現地観測とは扱わない。

1回答反転は `any` の最初の5反復だけで、最も低いスコアの「対象あり」を「なし」に、
最も高いスコアの「なし」を「対象あり」に各1件変える。最終標本を固定して再推定するため、
停止・延長の経路が変わる感度までは評価しない。旧報告の50反復より小さい探索的確認である。

**【事実】** スクリプト内で層の完全分割・重複なし・同値・ゼロ検出・seed再現・早期停止と未評価表示を検査する。
合成例に加え、実データ全76種×モデルで全窓に真のラベルを回答し、
選ばれた区切りのprecisionが真値・幅ゼロに一致することを検査する。
現行アプリのdensityの事後区間は全数回答でも幅ゼロにならないため、この検査はprecisionについて行う。

**【事実：上限の独立した検算】** N=25窓からn=8窓を無作為抽出する場合、
提案のJeffreys予測による片側95%上限は、陽性回答0件なら4窓、1件なら9窓になる
（`y + scipy.stats.betabinom.ppf(.95, N-n, y+.5, n-y+.5)`）。
真の陽性が5窓ある母集団では、上限が真値を下回るのは0件を引いたときで、
その確率は `hypergeom.pmf(0,25,5,8)=0.116469`。したがって被覆は88.353%である。
これはシミュレーションの乱数誤差ではなく、この上限を一律の「設計ベース95%保証」と呼べない反例である。
提案本文の `3N/n` 近似（この例で約9.4窓）とJeffreys予測の上限は同じものではない。

|---|---|---:|---:|---:|
| Perch V2 | C | 14.7% | 0.006 | 0.023 |
| Perch V2 | A1 | 7.2% | 0.004 | 0.015 |
| Perch V2 | G | 30.3% | 0.030 | 0.038 |
| Kinglet-B v0.2.0 | C | 12.6% | 0.009 | 0.028 |
| Kinglet-B v0.2.0 | A1 | 13.6% | 0.007 | 0.025 |
| Kinglet-B v0.2.0 | G | 27.6% | 0.025 | 0.038 |

**【事実】** Gは両モデルでCより決定状態が変わりやすい。A1はPerchでは改善し、Kingletでは12.6%→13.6%でわずかに悪化した。少数反復のため差の精密な判定はしない。**【推測】** Gの少数Dセンサスは少ない回答で完了できる一方、1回答の誤り・訂正が結論を変えやすい。

### 3.6 42/21,840窓の構造的な合成例

42陽性すべてが0.1以上、負例はすべて0.1未満という完全な順位付けを人工的に作った。200反復の抽出段階だけの比較で、推論・曲線・B1上限は評価していない。GはD完了時の標本を用いた。

| 方式 | 陽性ゼロ | 真陽性≥3 | 抽出陽性数の平均 |
|---|---:|---:|---:|
| C | 51.0% | 1.5% | 0.645 |
| A1 | 0.0% | 100.0% | 10.000 |
| G | 0.0% | 100.0% | 24.000 |

**【事実】** 最上位層は683窓。Cの最初の10抽出では平均42×10/683≈0.615陽性しか期待できず、陽性ゼロが約半数になる構造を再現した。実事例の61回答や全陰性の個々の音を再現したものではない。

**【推奨】** A1を次の候補とし、大きい実運用母集団・異なる地点で確認してから採用を判断する。見逃し全体や補正倍率を出す根拠にはしない。Gの回答削減だけを理由に、B1を95%保証、B3を評価済みと表示しない。

## 4. 再現方法と検証範囲

```bash
.venv/bin/python scripts/simulate_validation_fuji.py \
  --data-dir /path/to/fuji-sim/data \
  --score-cache /path/to/fuji-sim/scores \
  --workers 8
cd apps/sidecar
../../.venv/bin/python -m unittest -q
```

依存は既存 `.venv` の NumPy・SciPy・pandas・pyarrow・soundfile・onnxruntime。
追加パッケージは入れていない。標準では `any,boundary` 各200反復、反転5反復。
`--score-only` は採点だけを行う。スコアキャッシュは入力・モデル・コード等の識別情報が一致するときだけ再利用する。
集計JSONは `docs/benchmarks/validation-fuji-2026-10-29.json`、
各反復と反転の明細は指定キャッシュ内の `simulation/<実行識別子>/` に保存する。
音声・注釈・窓別スコア・各反復の明細はリポジトリに含めない。

### 一般化の限界

- 富士は元から2,160窓、今回の除外後は種ごとに1,484～1,534窓であり、実運用の21,840窓よりかなり小さい。
  少数Dの全数調査が多く、そこで出る狭い区間や小さい誤差を大規模運用の保証へ移せない。
- 38種のうち両モデルとも13種で0.1以上の検出がゼロ。錨になる集合がなければ、A1・Gでも
  上位の真陽性を集められるとは限らない。検出が少ないことと、希少だが順位付けが良いことは同じではない。
- A1は層を変えると現行推定の曲線の中心 `x0` も変わるため、抽出効果と事前分布の中心の効果を分離していない。
  Cのみ延長ありという回答予算の違いもある。結果はここで定義した方式全体の比較である。
- Perchの `rinphe2` はアプリの対応どおり *Phasianus versicolor* を使う。
  以前の報告がキジについて記した *P. colchicus* への置換は行わない。
  今回はアプリで得る値の評価であり、分類群とモデルの学習ラベルの意味を再監査する作業ではない。
- Gの良い被覆率・小さい誤差は、区切りが決まった一部の反復だけの値である。
  高い未決率や未調査のB1/B3と合わせて読む。ROC-AUCが高くても、希少種でprecision 90%の区切りを
  必ず得られるわけではない。録音間の重複・音の似方を新しい地域への独立な検証とは扱わない。
- 42/21,840の合成例は順位設計だけの検査であり、Perch・Kingletの実性能の証拠ではない。
  不確実な正解の除外方針、聞き手の系統的な誤同定、地点・季節・さらに大きい母集団は別途確認が必要。

**【事実】** 指定の既存テストコマンドは89テスト、OK（50.636秒）。
失敗経路を検査するテストの意図的な例外ログと依存の非推奨警告は出たが、失敗はなかった。
UI・配布ビルド・Windows・新しい録音地点での検証はこの評価の範囲外である。
